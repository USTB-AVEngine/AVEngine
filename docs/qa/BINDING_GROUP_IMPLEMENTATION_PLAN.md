# AVEngine 双模态必要性数据集：恢复原定设定的实施方案

## 1. 目标与既定约束

本轮交付**数据集生成、真实样本检查、评分接口和说明文档**。模型设计、训练和比较实验留到后续。

以下要求贯穿生成、重试和验收：

- **每个 Episode 内，相机位置、朝向和视场角保持固定。** 不同 Episode 可以按配置选择不同机位。
- **当前批次固定 10 秒**，沿用现有帧率、采样率和分辨率配置。时长及其他采样参数由数据配置驱动，不能为了生成成功而自行修改。
- 保留 **QA-01～25、Apartment／酷家乐／HM3D／MP3D、全部现有声源家族及来源组合**。不要求每一种题在每一种组合下都适用，但必须保留覆盖目标和缺额原因。
- 使用最终确认的声音池、事件参考峰值策略和统一后置增益 **0.5**；保留请求声明的尾音预留，当前为 **3 秒**。不做逐样本音量拉齐，不额外截断或拉伸声音来凑排程。
- 公开时间与角度使用整数；时间描述优先采用区间、事件顺序和片尾。新增跨时刻方位题首版统一询问**片尾状态**，真值取实际末帧。
- Apartment、酷家乐继续使用原生 UE；HM3D、MP3D 继续使用原生 Habitat。沿用现有资产和动作能力。

**主线是双模态必要性。** 画外、遮挡和实体运动是任务条件；纯 A、纯 V 题继续作为组件诊断，不混入主榜的双模态必要性结论。

## 2. 先纠正本轮偏离

在服务器权威工作副本中完成以下修正：

- 撤回本轮新增的转动相机配方及为它添加的音频路由改动；保留项目原先已有的其他能力。两段转动相机的画面保留在历史目录，不进入交付索引。
- 取消 16–18 秒安排。所有新排程在 **10 秒、既定尾音预算、合法运动速度和现有声音素材**内求解；不足时在相同条件内重试，耗尽既有重试预算后记录缺额。
- 新请求从最终生产配置继承声音池。复用旧画面时，分别核对视觉输入与当前音频输入，不能连同旧声音池一起照搬。
- 声音重分配后重新验证目标实体、声音类别、素材兼容性和原生发声绑定；允许一个实体拥有多个事件，不能把“一实体一事件”写成通用限制。
- 修复时间参数覆盖问题。显式参数替换默认值；未指定时从合法排程或查询区间中按配置抽样，不固定挑最短声音或固定查询时刻。

现有题库修正继续保留，但必须真正解决对应问题：

- **QA-20：**真实像素决定可见性，外观复核只决定能否命名；缺少外观标签不能变成“没有可见对象”。
- **QA-18：**整数区间内的短暂发声仍计入，缺证据不能当静默；恢复声明的合法候选均匀采样，不暗中改成答案类别优先。
- **QA-05：**重叠由实际发声活动区间求交。
- **QA-22：**选项不能直接泄露真实实体数量；干扰项满足合法计数关系。答案分布问题通过明确的场景采样配置处理，不修改真值，也不能只加诊断字段就宣称修复完成。

## 3. 固定相机下构造四类核心组

继续使用现有 QA 编号，通过任务变体区分新增机制。

| 核心任务 | 固定相机下的构造方式 | 必须验证的事实 |
|---|---|---|
| **可见实例绑定** | 交叉改变发声归属与已登记的视觉外观对应 | 回答随真实对应关系改变；音频复用须有实际声学输入一致的依据 |
| **视觉条件化声音关系** | 至少三个候选，题目指定其中两个；改变它们的发声排程或对应关系 | 所选对象对的重叠关系改变，其他候选保留，不能退化为全局是否有重叠 |
| **跨事件物理身份** | 使用真实连续实体轨迹，构造保持位置与换位等变体；调整后续事件的发声实体 | 判断的是同一物理实体，不能用换颜色、同声纹或同一声音文件代替身份 |
| **跨时刻状态** | 早期声音确定目标，声音及混响结束后实体沿合法路径运动，询问片尾方位 | 方位变化来自实体运动；相机固定，答案来自实际末帧观察 |

轨迹必须沿用原生导航和已有动作，不能传送、让静态设备自行行走，或新增手持物交接等机制。无法从公开画面辨认身份的样本不进入该任务组。

每个核心组通常包含四个成员，并满足：

1. **相同音频、相同题面，搭配不同视频后答案不同。**
2. **相同视频、相同题面，搭配不同音频后答案不同。**
3. 完整 AV 提供足以区分答案的公开证据。
4. 声学状态变化时重新渲染；不能为了凑共享音频而强行贴旧音轨。
5. 对声明答案不变的附加对照，同样检查真实媒体与真值；附加样本不冒充新的独立世界组。

固定相机和既定时长约束优先于配方成功率。

## 4. 接口、验证与交付顺序

沿用现有请求、分组和评分结构，不新增冻结机制或通用治理框架。

- **输入：**当前房间目录、资产登记表、最终声音池，以及显式的任务、条件、排程和查询参数。
- **公开输出：**音视频、题面、必要的相机标定和不透明样本编号。
- **私有输出：**原生读回、真值、分组关系、干预说明、实际覆盖和失败原因。分组身份、引擎实体 ID 和答案不得进入模型提示。
- **评分：**MCQ 与 Open 分开；保留逐题结果、整组全对率、关系一致性和现有角度指标。关系变化正确不等于答案正确；缺答和无效答案保留在对应分母内。

实施顺序固定为：

1. 完成上述纠偏和受影响行为的回归检查。
2. 用保留的真实输入复查原有 25 类题；只重新派生受影响部分。
3. 先验证“四类任务 × 四类房间”各一个小组，再扩到每格四个独立组，目标仍为 **约 64 组、256 个核心成员**。
4. 声源家族和来源组合按覆盖清单推进，不能用人声填掉其他家族的缺额。语义不适用、能力未实现、证据缺失和实际有效产出分别记录。
5. 完成项目要求的 fast-unit 检查、真实媒体核验、审阅入口和文档更新。

重点测试包括：相机仅旋转也应被拒绝；时长或尾音预算不符应失败；显式参数正确覆盖；不兼容声音重分配被拒绝；缺活动证据不生成静默答案；实际共享 PCM／视频与声明一致；公开输入不泄漏答案。

当前通过检查的一个静态组可保留，其两次导出仍只计一个独立组。人工可答性、模型评测和正式准入必须报告实际状态，机器检查通过不能替代这些证据。本轮不包含推送、合并或正式发布。

## 5. 你最终要达到的目的

**你的最终目标，是形成一项面向 CVPR、以“必须联合音频与视觉才能回答”为核心的研究贡献。**

AVEngine 要提供可重复、可扩量、具有真实空间音频和逐帧依据的数据；通过受控成组样本，证明主榜问题确实需要两种模态，并支持区分：

- 声音没听对；
- 画面没看对；
- 两边分别感知正确，却把事件与实体对应错；
- 对应正确，但后续关系或时间推理出错。

后续模型工作应在相同输入和预算下，检验这些关联与推理错误能否被改善。**这轮数据集工作的目的，就是把上述研究主张变成可以被检验的实验对象；模型是否存在这些短板、改进是否有效，都由之后的实际结果回答。**
