## 3. 已确认的设计缺陷(codex 指出,我复核属实)

### 3.1 卡①:MCQ 与开放版**均未准入**

- 40 条目标角落在 `[-31.2°, +7.9°]`,其中 **38/40 为负角**(初版报告里
  写的"左右 21:19"是移动者终点的左右侧计数,**不是目标答案分布**,该
  说法作废);
- 在占位计分(±15° 满分 / ±30° 半分)下,**恒答约 −15.86° 平均得
  96.25%**,37/40 满分、40/40 至少半分 —— 开放版已退化成常量猜测题;
- 四方向 MCQ **40/40 退化为"前"**,被编排器上游复检全数拒出;
- 工单要求的两只片尾角距 `> 2×THETA_HALF`(占位下 60°)**只有 4/40**
  达标,当时过滤用的是 MCQ 口径 25°,**开放题约束没有落实**。

处置:**当前 MCQ 与开放版都记为未准入**,只作失败诊断。根因是观测协议
——固定前视视频要求目标片尾可见时,目标天然只能位于视锥内,四扇区不可
能覆盖;这不是加几个机位能解决的。已量化的更硬事实:在**固定机位**下,
"片尾可见 + 锚后仍有足够角位移"这对联合约束把答案锁死在 +17.5° 以左,
视锥右带全锚帧范围**零可行组合**。修复方向见第 5 节(相机由通用采样器
自动搜索,答案带由解 yaw 构造)。

### 3.2 卡⑧:时间带只能算开发期观察

首叫被压进前 2.58 秒(继承了卡① 的 1.5 秒片尾静默),原四带后两带
结构性为空。**看完数据再切出来的 0.65 秒带不能反过来认证 run01**:

- 新四带总分布 54/60/73/53 看似尚可,但**按外观拆开后**黑白狗是
  22/21/48/29 —— 只看外观猜第三带即得 **40%**,黄狗最佳先验 32.5%,
  所以 V-only 条件基线**不能按 25% 写**;
- 开放版在 ±0.3/±1.0 秒占位计分下,**恒答约 1.657 秒平均得 54.17%**。

"所有答案都在前 2.6 秒"不会直接指出哪个选项对,但它暴露调度模板、让
模型可以忽略视频后半段、抬高开放题常量基线,并削弱"全视频时刻锚定"的
论文表述。

### 3.3 卡⑦/⑨:偏斜与固定槽位绑定

- 卡⑦ 55:41(黄:黑白,负样本另计)、卡⑨ 73:47;
- **全局 47:47 的均衡子集不足以证明条件均衡**:该子集内只按运动类猜
  多数类仍有 **57/94 = 60.6%**;
- 更要紧的是 run01 **全部 120 个主点固定 `source1=黑白狗`、
  `source2=黄毛狗`** —— 只要音频方向、槽位模板或时序能识别 source slot,
  就能间接推出外观答案。12 个外观孪生只能**诊断**这件事,替代不了设计
  上的反平衡。
- 卡⑦ 还把 24 个 `neither` 混进了 120 条主集统计,违反工单"主集只出
  恰好一只在叫"的要求,且没有 `both` 对照。

### 3.4 卡⑯:等像素掩码通道

本批捕获只有 rgb 与帧记录,没有像素遮挡真值。按工单 1.8 的顺序,掩码
通道接入后对本批(原始数据已保留)补渲并逐题复核卡①⑦ 的几何可见性
判定,再出卡⑯。

## 4. 执行事故与教训(已制度化)

- 半成品目录被调度器的守卫两次拦下,人工确认为空目录后手动清理 ——
  守卫不自动清理的设计有效。
- 外观孪生直接复用主点 program 被渲染链 fail-closed 拒绝(endpoint 绑定
  随资产翻转)→ 新增孪生 program 派生器,按登记表口径换绑重密封。
- 远端 `pkill/pgrep -f` 的模式串会匹配承载它的 shell 自身(自杀两次),
  模式改用拼接变量构造。
- program 的候选 endpoint 不是自由命名:渲染链按(资产×实例×锚点)在
  登记表 fail-closed 匹配。
- **引擎侧真缺陷**:音频渲染只交叉校验相机**位置**,听者**朝向**完全
  取自 M1 请求 —— 逐点改相机 yaw 会画面转、双耳不转且**不报错**。已修
  (提交 6fbaf2c),10 项测试。这条是查"卡①能否靠变相机救"时发现的。

## 5. 修法与后续(run02 的前置)

已实现并入库:

1. **通用场景采样器**:手挖走廊库 + 固定相机 → 场景无关求解器;路线库
   适配器按**库自己的 schema** 分派(不按房间 ID);答案带由解 yaw
   构造而非枚举撞出;拒绝按原因计数并留首例。
2. **题型专用 AudioProgram**:①F 正向(锚在最后一声、锚后按片长比例
   静默)、①B 反向(锚在末段、**查询时刻附近目标必须静**)、卡⑧(不
   继承片尾静默、首叫落进预声明带)、卡⑦(查询帧恰好一个发声者);
   发声者用语义角色,绑定槽位是后一步。
3. **先分配答案再采样**的批级反平衡:槽位↔外观绑定、first_slot、
   卡⑧ 答案带对、卡① 方位带各自独立配额并独立洗牌(轮转会让因子周期
   互锁,成为跨卡泄漏)。
4. 卡⑦ 主集与"都没叫"对照拆成不同文件分别统计;均衡子集改为切分后按
   `split × 运动类 × 真值`分层选取。

**设计层跨场景 smoke —— 准确口径**:**2 个场景资产、2 类后端、3 个
路线域**(HM3D 的两个楼层是同一栋房子里的两个路线域,证明同场景内不同
几何区域可复用规则,**不是**两栋独立房子)。产出统一标记为
`geometry_candidate`(设计期/渲染前候选),**不是题目准入** —— 三个
路线域的 `line_of_sight_screened` 全为 false,没有任何视线或像素证据。

配额填满不等于通过率 100%,真实分母如下(每轮抽一个
相机×路线×转折帧组合):

逐带明细也已入库(例如 apartment ①B 的右带明显更难:平均 7.25 次、

**"同一份配置"分层**:相同的是题型 profile、方位带、时间关系、采样
参数、语义角色与拒绝规则;不同的是各后端的路线库 schema 适配器
(UE 是 (x,y) 厘米、habitat 是 (x,z) 米),适配器名逐场景记录。

**本轮能声明的**:题型约束可由场景无关的几何求解器作用于两个不同场景
资产与两类后端输入;正向/反向错时与卡⑦⑧ 的音频调度可由题型 profile
表达。**不能声明**:三个独立场景全部准入、采样通过率 100%、跨场景渲染
已完成、run02 已具备启动条件。

run02 的启动条件(未满足前不跑):通用采样器完成、题型专用 AudioProgram
完成、①F/①B 协议完成、槽位与外观解绑、卡⑦ 主集与对照拆分、卡⑧ 时间带
预先锁定、**至少两个真实可渲染场景通过同配置端到端 canary**。run02 仍
是 research candidate。
