# 给同学 A 的说明:做"会发声的东西"的 3D 模型(2026-08-30)

你负责的是:场景里会发出声音的物体的 3D 模型,比如音响、冰箱、微波炉、猫、狗。
我们把这些模型摆进虚拟房间里让它们"发声",再渲染出声音和画面,用来出题。

## 现在的情况

模型库里已经有 44 个做好的模型,所以你暂时没有着急要做的事。以后群里会提需求,
比如"要一只橘猫""要一台立式洗衣机",到时候按下面的流程做就行。

## 先把页面打开

在你自己电脑的终端里跑这一条(把尖括号换成你自己的服务器别名):

```
ssh -L 8765:127.0.0.1:8765 <你的服务器别名>
```

然后浏览器打开 http://localhost:8765 ,点页面最底下的"声源资产台"。
每个模型旁边都写着机器量出来的结论,比如摆得正不正、尺寸对不对。
**合格不合格以页面上的结论为准**,不用自己猜,也不用问人。

模型文件都放在服务器的这个目录下,一个模型一个文件夹:

```
/data/avengine_external/assets/sound_source_assets_v1/<类目>/<物种或型号>/<变体>/
```

文件夹里有三样东西:`asset.json`(这个模型的体检报告)、`finalized.glb`(模型本体)、
`emitter_marker.glb`(标出"声音从哪个点发出来"的可视化文件)。

## 做一个新模型的流程(三步,脚本都是现成的)

1. **用 AI 生成一张这个物体的图**。用 `avengine-imagegen` 这个 conda 环境,
   模型在 `/data/models/hub/models--black-forest-labs--FLUX.2-klein-4B`。
   参数照抄:guidance_scale 填 1(这个模型就要填 1,填大了反而坏)、跑 28 步、
   出 1024×1024 的图。
2. **把图里的物体抠出来**(去掉背景)。跑 `tools/assets/segment_canonical_2d.py`,
   用 `hunyuan3d` 这个环境,CPU 几秒钟就完。
3. **把图变成 3D 模型**。跑 `tools/assets/run_pixal3d_mesh.py`,用 `avengine-3dgen` 环境。

## 跑之前必须设好的东西(每一条都有人踩过坑)

- 先 `export HF_HOME=/data/models`。不设的话,程序会去别的目录找模型,找不到
  就自己悄悄从网上下载 23 个 G,你会白等十几分钟还不知道为什么。
- 再 `export ATTN_BACKEND=sdpa`。这个环境里没装 flash_attn,不设会报错。
- 第三步的命令要带 `--pixal3d-root /data/jzy/code/Pixal3D-lead-b`,指错了会两个版本混着用。
- 第三步还要带 `--resolution 1024`。默认是 1536,会在算网格的时候把显存爆掉;
  改成 1024 不但不爆,一个模型还能从 13 分钟缩到 6 分钟。
- 要做很多个模型的话,**一个模型跑一次命令**,不要写个循环在同一个进程里连着跑
  ——两个大模型会一直占着 20G 显存,跑到第二个必爆。

## 模型出来之后,常见的三个毛病

1. **模型是歪的**:生成的模型普遍往前倾 5 到 27 度。用仓库里现成的纠正脚本,
   它会在正负 35 度里搜一个让模型"放得最平"的角度。别自己写。
2. **包围盒是斜的**:对正朝向要用仓库里现成的方法(凸包最小外接矩形)。
   有人用过 PCA,结果把一台烤盘车转歪了 45 度,后面摆放全错。
3. **厚度不可信**:单张图猜 3D,"深度"这个方向最不准。体检报告里可以填真实产品
   的宽和深来校正。要是某个模型烂到救不回来(比如电视被重建成 1 米厚的砖),
   直接扔掉重做,不要硬修。

还有两个先例记住就行:挂墙的东西如果实在没有平整的安装面,体检报告里如实写
"没找到安装面",不算你的错;屏幕类(电视)歪一点有专门的豁免规则,机器会另判。
