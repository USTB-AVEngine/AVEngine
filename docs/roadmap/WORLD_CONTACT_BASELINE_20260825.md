# 世界接触基线验证（20260825，只读）

> 目的：判断现有"世界接触"验收标准是否失效，并给出可自动化的替代判据。
> 方法：**完全离线**——从 m2 包自带的静息骨架 + 烘焙旋转做正向运动学（FK），
> 不渲染、不占 GPU、不写任何文件。脚本：`/data/jzy/tmp/world_contact_baseline.py`、
> `/data/jzy/tmp/implied_speed_check.py`。被测对象：`rocketbox_beagle_m2_canary_v7_world_contact_r5`
> （状态 `canary_qualified`，即"已通过现行验收"的资产）。

## 0. 结论先说

现行验收标准**确实不够**：一个已经通过验收的资产，在三项可量化指标上都有问题，
其中**步速失配**是影响所有已产出批次的真实缺陷。

| 指标 | 实测（比格 walk / idle） | 判断 |
|---|---|---|
| 支撑面倾角（idle） | 中位 1.97°，最大 3.20° | 勉强合格，但无量化门槛可依 |
| 四爪高度差（idle） | 最大 **2.58 cm** | 站立时有爪子悬空 |
| 接触相位标注（walk） | 主导模式为**单脚支撑**，且 **5/25 帧四脚全空** | **不符合 walk 步态**，疑似"最低脚"标注 |
| 着地期滑步 | 中位 **1.98 cm/帧**（≈0.30 m/s） | 无门槛，未被任何检查捕获 |
| **动画隐含步速 vs 配置步速** | 隐含 **≈0.33 m/s** vs 配置 **0.72–0.77 m/s** | **差 2.2 倍，是滑步的根因** |

## 1. 数据结构（为什么这套检查可以全自动）

m2 包的运行时是**纯旋转 + 固定骨长**：

```
actions/walk.npz : walk.rotations_xyzw [25, 34, 4]   ← 只有旋转，无位移
skeleton.json    : 35 关节的 local_translation_m / rest_rotation_xyzw / parent
                   runtime_joint_order（34，不含根关节）
                   actor_from_skin_root（Biped 骨架是 X-up，此矩阵映射到 actor 的 Y-up）
asset_manifest   : anchors 把 paw_front_left 等绑到具体关节（L/R Finger0、Toe0）
coordinate_system: up=+Y, forward=-Z, 右手系, 米
```

因此**每帧四只爪子的位置是闭式可算的**，所有质量指标都能离线得出——
不需要人看视频，这正是把"迭代 12 轮"变成"跑一次出五个数字"的基础。

> 踩坑记录：直接在蒙皮空间量会得到支撑面倾角 ≈85°（因为 Biped 的"上"是 +X）。
> 必须先用 `actor_from_skin_root` 转到 actor 帧。这个坑本身也说明为什么需要
> 标准化的检查脚本而不是每次手算。

## 2. 逐项实测

### 2.1 支撑面与站姿（idle 才是有意义的量测对象）

| | walk | idle |
|---|---|---|
| 支撑面倾角 中位/最大 | 9.78° / 15.88° | **1.97° / 3.20°** |
| 四爪高度差 中位/最大 | 6.04 cm / 12.46 cm | **1.66 cm / 2.58 cm** |

walk 期间倾角大是正常的（迈步时腿本来就有高低），所以**支撑面判据只应对 idle/静息姿态生效**——
资产契约里"四足支撑面必须水平"说的也是资产帧，这一点现有文档没写清楚，容易误用。

idle 的 1.97°/2.58 cm 属于"能用但不够干净"：站立时有爪子悬空近 3 cm。

### 2.2 接触相位标注质量（问题最明显的一项）

统计 25 帧的支撑模式：

| 动作 | 模式分布 | 判断 |
|---|---|---|
| idle | (1,1,1,1) × 25 | ✓ 正确 |
| **walk** | 单脚支撑 12 帧、双脚 5 帧、**零脚 5 帧**、其余 3 帧 | ✗ 不是 walk |

四足动物的 walk 步态**任何时刻至少 2–3 只脚在地，绝不腾空**；腾空是 trot/gallop。
现在这份数据要么是"只标最低那只脚"，要么阈值过严。用我从几何推导的接触相位与它比对，
**一致率只有 82%（walk）/ 69%（idle）**。

这正好命中资产契约里那句警告：*"逐帧最低脚接地 + 后期 Z 平移只解决垂直接触，
不能证明四足支撑面是水平的"*——**现行数据就是这个失败模式**。

### 2.3 步速失配（本次最重要的发现）

动画是**原地**的（只有旋转），所以着地的爪子在 actor 帧里向后移动的速度 = 身体
前进速度。用三种互不依赖的估计器：

| 估计方式 | 结果 |
|---|---|
| 最低爪逐帧位移 | 0.332 m/s |
| 低高度爪集合 | 0.364 m/s |
| 逐爪分别估计 | 0.302 / 0.358 / 0.407 / 0.422 m/s |
| 步幅 | 0.553 m / 周期（周期 1.667 s） |

**动画自身隐含的自然步速 ≈ 0.33 m/s。**

而我们的配置是：

| 来源 | 速度 | 与动画的比值 |
|---|---|---|
| `motion_profiles_v1.json` 犬类带 | 0.60–0.78 m/s | **1.8–2.4×（太快）** |
| batch2d 实测 | 0.72–0.77 m/s | **2.2–2.3×** |
| pilot48 实测 | 0.157–0.394 m/s | 0.5–1.2×（低端太慢） |

**根因在渲染器**：`src/avengine/m5/current_apartment_visual.py:359` 的步相是

```python
period = int(binding["walk_phase_period_frames"])          # = 25，常数
phase  = float((frame_index - walk_start) % period) / float(period)
```

**步频只按帧号推进，与移动速度完全无关**；而位移是起点到终点线性插值。
于是 batch2d 里狗的脚**每秒滑 ≈0.42 m**，5 秒累计滑移约 2.1 m。

这也解释了 pilot48 那次"移动不自然"的观感：0.157 m/s 时是**腿动得比身体快**（原地踏步/月球漫步），
我们把速度提到 0.75 m/s 之后变成**身体跑得比腿快**（前向滑行）——两次都不对，
因为**从头到尾没人问过动画本身要求多快**。

我们当时的速度带是按"房间对角线 / 5 秒"这个**几何**约束定的，不是按**动画**定的。
这是我引入的方法性错误。

## 3. 建议的新验收判据（可自动化、可回归）

对每个新资产（以及回归已有资产）离线计算，全部有明确门槛：

| # | 判据 | 建议门槛 | 现状 |
|---|---|---|---|
| 1 | idle 支撑面倾角 | ≤ 2.0° | 比格 1.97°（勉强） |
| 2 | idle 四爪高度差 | ≤ 1.0 cm | 比格 2.58 cm ✗ |
| 3 | 着地期滑步 | ≤ 0.5 cm/帧 | 比格 1.98 cm/帧 ✗ |
| 4 | 穿地深度 | ≤ 0.5 cm | 待测 |
| 5 | 步态支撑模式 | walk 不得出现腾空帧；≥2 脚支撑占比 ≥ 80% | 比格腾空 5/25 ✗ |
| 6 | **动画隐含步速** | 作为**该资产的速度带中心**，允许 ±20% | 未使用 ✗ |
| 7 | 接触相位一致性 | 几何推导 vs 存储标注 ≥ 95% | 比格 82% ✗ |

判据 1–5、7 用来**验收资产**；判据 6 用来**驱动生产配置**——即
`motion_profiles_v1.json` 的速度带应当由动画反推，而不是拍脑袋。

## 4. 对现有数据的影响（诚实评估）

- **不影响已出题目的正确性**：滑步不改变"谁先发声、在哪一侧、当时是否在动"这些答案；
- **影响画面真实性**，是 reviewer 可能攻击的点（"你们的合成数据有明显滑步"）；
- **建议在扩到 3000 点之前修**，因为修的是配置和一处渲染逻辑，越晚修重渲越贵。

两条修法（可并用）：
1. **把速度带对齐动画**（最简单）：犬类改为 0.33 m/s ± 20%；
2. **让步频随速度缩放**（更灵活）：`period = round(25 × implied_speed / actual_speed)`，
   即走得快步子也迈得快，可以保留自然的移动速度而不滑步。改动只在
   `current_apartment_visual.py` 的相位计算处，需配套等价性回归。

## 4.5 人物实测：失配方向正好相反（20260825 补测）

用同样方法测了 Habitat 人物运行时（`tmp/m5_1/human_runtime_api_probe`，
GLB 层级 + 逐帧 TR，`root_motion_contract = static_rest_owned_by_articulated_object`
即同样是原地动画）：

| | 隐含步速 | 周期 | 步幅 | 配置带 | 失配 |
|---|---|---|---|---|---|
| 人物 Walking | **1.384 m/s**（逐脚 1.22–1.40） | 1.067 s / 16 帧 | 1.48 m | 0.60–0.78 | **只有 54%，腿快于身体** |
| 比格 walk | **0.33 m/s** | 1.667 s / 25 帧 | 0.55 m | 0.60–0.78 | **2.2 倍，身体快于腿** |

1.384 m/s 正是教科书上的成人步速（1.2–1.4 m/s），说明测量可信。

**于是同一条速度带把两个物种推向相反的错误**：batch2d 里 144 个人物点在"原地踏步"
（滑步比 46%），48 个犬类点在"前向滑行"（滑步比 56%）。根因就是这条带是按房间几何
定的、对所有物种一视同仁，而两种动画的自然步速差了 4 倍。

**房间约束是真实的**：公寓外壳对角线 / 5 秒 ≈ 0.79 m/s 是上限，所以**不能**简单把人提到
1.38 m/s（会走出房间）。这正是需要步频缩放而不是只改配置数字的原因。
