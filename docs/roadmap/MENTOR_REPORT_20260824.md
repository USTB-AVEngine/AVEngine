## 0. TL;DR

1. **发现并否证了旧数据**：此前积累的 1000 episode / 约 1 万条 QA（v1）**不支撑论文核心命题**——问句里点名物种（"在叫的那只狗"）且每场景每物种唯一，导致单看画面即可作答。零样本模型 AV 比纯视觉只高 2 个点。该批数据已降级为管线试验田，不进论文。
2. **重建了题型与认证方法**：改为**跨模态指代 QA**（用一个模态指代对象、用另一个模态提问），配"同资产轮流发声"设计（两个声源用**完全相同**的声音和外观，身份只能靠空间+时序区分），并落地三道机器可核验的认证闸门。
3. **打通了生产管线并产出两批数据**：pilot48（48 点 / 194 题）+ batch2d（192 点 / 909 题）。实测产能：视觉 **192 点 / 80 分钟**（≤2 卡），音频 **192 点 / 194 分钟**（3 路 CPU）。
4. **零样本基线证明了命题成立**：Qwen2.5-Omni-7B 在需要双模态的题上 **AV 仅比纯视觉高 0.8 个点**（二选一，随机线 50%）——模型拿到空间音频用不上，这正是论文要打的空白。
5. **首轮微调证明了数据可学**：SO-7B 在**从未见过的** held-out 上 **70.9%**，超零样本 AV **+16.4 个点**；但时序绑定类题目（"第二声说话时那个人在动还是静止"）**完全没学会**（模型 100% 常量作答）——这是当前最硬的难点，也是论文的核心卖点所在。

## 1. 论文命题：我们要证明什么

**核心命题**：构造并**认证**一批"必须听觉+视觉同时参与才能回答"的问题——单看画面答不了、单听声音也答不了。

**题型骨架（跨模态指代）**：指代用一个模态，提问用另一个模态。
- `R-A × Q-V`：**用声音指代人、问他的视觉属性**——"先说话的那个人穿蓝色还是绿色上衣？"
- `R-V × Q-A`：用外观指代人、问他的声学属性——"穿绿衣的那个人的声音来自画面左侧还是右侧？"
- `R-A × Q-S`：用声音指代、问空间关系——"第一声说话时，说话人离相机更近还是更远？"
- `R-A × Q-T`：用声音指代、问时序状态——"第二声说话期间，说话的人在走动还是静止？"

**认证闸门（论文的方法贡献之一，全部机器可核验）**：

| 闸门 | 含义 | 判据 | 当前结果 |
|---|---|---|---|
| A · 路线互换 | 换音频路线后答案必须翻转 | 反事实音频 | v1 已有 620 对孪生音频；v2 沿用设计 |
| B · 属性孪生 | 两人外观互换后，属性题答案翻转、几何/时序题答案不变 | 逐题比对 | **batch2d 320/320 通过**（64 对孪生 × 5 题型） |
| C · 纯文本 | 不给音视频时准确率不高于随机 | text-only 推理 | **909 题 51.6%**（随机线 50%）通过 |

**与相关工作的区别**：现有音视频 QA benchmark（如 MUSIC-AVQA 系列）多为"看得见即可答"；空间音频方向（CVPR 2026 "Hear you are" 等）多为真实录制、难以做反事实与属性孪生。我们的差异点是：**受控生成 + 可认证 + 数值 DoA 题型 + 针对模型失败模式设计**。

## 3. 关键否证：v1 数据为什么不能用（本轮任务 1）

先做诚实盘点（数据不在交接文档列出的候选路径，在一块没被盘过的目录里），再做量化评估，结论如下：

| 轴 | 结论 |
|---|---|
| **双模态必要性（核心）** | **不成立**。问句文本泄漏物种（bark=狗、meow=猫），且每场景每物种至多一只 → "用音频锁定个体"这一步被文本替代，视觉单模态即可作答 |
| 认证覆盖 | 仅 ATTR/AVREL 有认证路径；**5397 题（75%）not_applicable**；refused 中"换路线答案不翻" 317 例 |

| 输入管线混淆 | 模型管线把双耳折成单声道（`[[76800]]`），ILD 线索在输入端即被抹掉——不能报成"模型不懂空间音频" |

| 合规 | 房间合规、全链 research_candidate ✓；但出自 legacy 多仓引擎，不满足"单仓新鲜生成"铁律 |

**处置**：v1 降级为管线试验田（owner 拍板豁免，仅作研究试跑），论文数据全部由现 main 单仓引擎重新生成。

## 4. 方法重建：v2 题型 + 反向拟合

### 4.1 关键设计：同资产轮流发声

两个声源使用**完全相同**的声音素材（同一段人声/同一段犬吠）与**同款**外观（仅上衣颜色不同的同一 Rocketbox 人物），于是：
- 声音本身**不携带身份**（同一段波形），身份只能由**空间位置 + 发声时序**决定；
- 外观差异（蓝/绿/酒红上衣）只能由**视觉**读取；
- 于是"先说话的那个人穿什么颜色"**必须**跨模态：先用空间音频定位谁先说，再用视觉读他的颜色。

为此在引擎侧注册了 3 个受控换色人物变体（同一 mesh、同一动画、仅材质换色），并把音频链从硬编码的"人+狗"泛化到**任意注册配对**（含发声顺序 a-first / b-first 两套程序，防止答案偏置）。

### 4.2 反向拟合（题目驱动生成，而不是先渲染后挖题）

先定题型配额 → 反推场景约束（走廊分离度、锚帧侧向、运动状态、发声顺序）→ 再生成。原因：从既有渲染里"挖题"的产出率只有 **12%**，且被拒的原因全在生成侧（视角、分离度、时序）。

配套设施：
- **走廊库**：从 v1 真实走过的路径里挖出 38 段近直线弦（已证明无家具阻挡）；
- **每物种速度带**（`motion_profiles_v1.json`）：人/狗 0.60–0.78 m/s、猫 0.50–0.70 m/s，上限由"房间对角线/5 秒"决定——从上层强制步速自然（此前 0.14–0.18 m/s 的"滑行"是被 owner 当场否掉的）；
- **锚帧侧向闸门**：发声瞬间两人必须在画面左右两侧可分（叉积判定，已用渲染帧人工核验）；
- **最小间距闸门**：两人任意时刻 ≥60 cm（防碰撞穿模）。

### 5.4 模型底座：Spatial-Omni 是什么，我们改了什么

**Spatial-Omni 本身**是一个"给已有全模态 LLM 补上空间听觉"的轻量方法（*Spatial Audio Understanding Integration in Multimodal LLMs via FOA Encoding*）。它的出发点与我们遇到的问题完全一致：现有 Omni 模型都把音频当单声道处理，方位线索在输入端就被丢掉了。做法是**不动宿主模型原本的音频编码器**，另挂一个 SO-Encoder（BEATs 基座、空间预训练），把一阶 Ambisonics（FOA，四通道 W/Y/Z/X）压成 **2.5 Hz 的低速率空间 token**，通过 `<|spatial|>` 占位符作为**独立模态**注入 LLM，因此额外上下文开销很小。配套资产为 SO-Dataset / SO-Bench（40 万 FOA 片段、210 万 QA、16 个空间子任务），训练分三阶段：先只训投影器 → 再加 LLM LoRA（编码器仍冻结）→ 最后解冻 SO-Encoder。我们用的 SO-7B = Qwen2.5-Omni-7B + SO-Encoder。**关键限制：原版是纯音频的，没有视频通路**，而我们的题目必须看+听同时用。

**我们的改动**集中在三处：

| # | 改动 | 内容 | 为什么必要 |
|---|---|---|---|
| ① | **视频通路** | 记录级 `video_path`；ffmpeg 管道解帧（环境无 PyAV/cv2/decord，零新依赖）；前缀扩成 `<|video|><|AUDIO|><|spatial|>`；接处理器 videos/fps/max_pixels；修 `video_second_per_grid` 张量；bs=1 守卫；replay+video 显式报错 | 从"纯空间音频 QA"变成视频+空间音频+文本的全模态 QA |
| ② | **时间对齐位置编码开关**<br>`so_time_aligned_media` | 改 `modeling_so_thinker.py`（49 行）：三模态共享 40ms 绝对时间轴，同时刻 token 拿相同时间 id；**默认关闭时与原实现逐位等价**（4 个单测锁住） | 我们自己的方法点候选，也是本轮消融的唯一变量 |
| ③ | **评测装置补 AV** | bench 脚本镜像训练侧视频通路；`with_video`/时间对齐**自动从 checkpoint 的 train_args.json 继承** | 否则评测会悄悄少喂一个模态，分数失去意义 |

**一个必须说清的数据侧折中**：我们的音频是双耳的、不是原生 FOA，所以现在用 mid/side 折出伪 FOA（`W=(L+R)/2, Y=(L−R)/2, Z=X=0`）喂 SO-Encoder，同时把 W 通道当单声道喂 Qwen 自带音频塔——这正是"缺前后与俯仰线索"的根源（见 §5.5 观察 ②）。训练上**直接从他们发布的 stage-3 产物续训**（`beats_lora` 模式），跳过前两阶段：空间通路本身已预训练好，我们要教的是"把空间线索与视觉身份绑起来"这件新事。

改动已镜像为 AVEngine 仓库分支 `spatial-omni-avengine-av`（原仓库非本项目所有，无推送权限）。

### 5.5 模型结构与 token 流（实测于一条真实训练样本）

配图版另开一页（结构图 / token 流图 / 位置编码对照图）：**[模型结构与 Token 流](https://claude.ai/code/artifact/28b9d118-5a39-487a-ad63-35697414af06)**

**四条输入通路**（5 秒片段 + 一道二选一题）：

```
成片 mp4（75 帧 5s）─抽 16 帧 336×588→ Qwen ViT（冻结）────────→ 2016 视觉 patch token
FOA 的 W 通道（折单声道）────────────→ Qwen 音频塔（冻结）─────→  125 单声道声学 token
FOA 四通道 [W,Y,Z,X] ───→ SO-Encoder（BEATs，10Hz，训练 162M）
                            └→ 投影器 pixel-shuffle ×4（训练 5.1M）→   13 空间 token（2.5Hz）
题干 + 选项文本 ────────────────────→ 分词器 ───────────────────→   27 文本 token
                                                                    ─────────────────
序列顺序 <|video|><|AUDIO|><|spatial|>⏎题干⏎答案<eos>  合计            2183 token
   → Qwen2.5-Omni Thinker（7B，主干冻结 + LoRA r16 α32，训练 40.4M）→ 答案 2 token
```

| 模态 | 编码器 | 速率 | token | 占比 | 是否训练 |
|---|---|---|---|---|---|
| 视频 | Qwen ViT + 2×2 patch 合并 | 403/s | **2016** | **92.3%** | 冻结 |
| 音频 | Qwen 音频塔（Whisper 式） | 25/s | 125 | 5.7% | 冻结 |
| **空间** | SO-Encoder（BEATs）→ 投影器 ×4 | 2.5/s | **13** | **0.6%** | 训练（167.2M） |
| 文本 | 分词器 | — | 27 | 1.2% | LoRA 40.4M |
| 答案 | — | — | 2 | 0.1% | **唯一计损失** |

**三条可操作的观察**：

1. **模态预算严重失衡**：视觉 403 token/s vs 空间 2.5 token/s，**相差 161 倍**。"模型忽略空间音频"可能有一部分不是学不会，而是预算根本不对等。低成本对照实验：投影器 shuffle 从 ×4 改 ×2/×1（空间 token 升到 25/50 个），或降低视频 token（8 帧 / 更小 max_pixels）。
2. **伪 FOA 缺前后与俯仰**：当前四通道是双耳折的（`W=(L+R)/2, Y=(L−R)/2, Z=X=0`），Y 只编码左右，**Z（上下）与 X（前后）恒为零**——"声源在身后"这类线索在输入端就不存在。原生 FOA 通路已过首个冒烟，是提升上限最直接的一项。
3. **监督信号极稀疏**：2183 个 token 里只有 **2 个**参与损失，其余 label = −100。MCQ 设定下合理，但每样本梯度信息极少——这也解释了为何 909 题规模下时序绑定学不出来。Setting-2（reasoning，带推理链）会把监督 token 数提高一到两个数量级。

**位置编码**（本轮消融的唯一变量）：legacy 模式下三段位置 id 首尾相接（视频 0–2015、音频 2016–2140、空间 …2153），"第 2 秒的画面"与"第 2 秒的声音"位置 id 相差两千以上；时间对齐模式（`so_time_aligned_media`）把三个模态放到同一条 40ms 绝对时间轴上，同一时刻的 token 拿到相同时间 id，默认关闭时与旧实现**逐位等价**。

## 6. 实验结果

### 6.1 零样本基线：命题成立（Qwen2.5-Omni-7B，pilot48 v2 题 189×3 条件）

| 分组 | n | AV | V-only | A-only | **AV−V** |
|---|---|---|---|---|---|
| 总体 | 189 | 54.5 | 53.4 | 51.3 | +1.1 |
| **dual_required（需双模态）** | 125 | 49.6 | 48.8 | 53.6 | **+0.8** |
| 视觉主导对照（谁更近） | 47 | 70.2 | 70.2 | 53.2 | +0.0 |
| 纯音频对照（左右侧） | 17 | 47.1 | 41.2 | 29.4 | +5.9 |

**读法**：视觉对照 70.2% 说明题目本身可答（排除"题出坏了"）；而在需要双模态的题上，模型拿到音频**几乎没有增益**（+0.8pp，二选一随机线 50%）。**这就是论文的空白点**。

### 6.2 首轮微调：数据可学（SO-7B，训练 batch2d 790 题，测 pilot48 held-out 189 题）

| 题型 | n | **微调 SO-7B** | 零样本 Qwen AV | 提升 |
|---|---|---|---|---|
| **总体** | 189 | **70.9** | 54.5 | **+16.4** |
| T9 谁更近（视觉主导） | 47 | 97.9 | 70.2 | +27.7 |
| T2 跨模态指代颜色 | 47 | 80.9 | 57.4 | +23.4 |
| T4 声源左右（纯音频） | 17 | 64.7 | 47.1 | +17.6 |
| TA 发声瞬间动/静 | 39 | 59.0 | 41.0 | +17.9 |
| **T7 第二声期间动/静** | 39 | **41.0** | 48.7 | −7.7 |

训练成本：单张 4090D 48GB，3 epochs × 约 1 小时，峰值显存 30.7 GB。

### 6.3 消融：时间对齐 RoPE 在当前规模无收益（如实汇报）

我们实现了一个方法候选：让视频/音频/空间三路 token 共享同一时间原点（40ms 网格对齐），作为可开关的消融项。同数据两跑：

| 配置 | valid EM（ep1/2/3） | held-out 总体 |
|---|---|---|
| 时间对齐开 | 55.5 / 64.7 / 56.3 | 67.2 |
| 时间对齐关（legacy） | 51.3 / 65.5 / **73.1** | **70.9** |

**结论**：909 题规模下时间对齐**没有收益**（总体反低 3.7pp），且最该受益的时序题 T7/TA 两跑**逐题输出完全相同**——因为模型还停留在"常量作答"阶段，根本没进入"用时序"的层次。处置：保留双跑记录，**3k 点规模复测后再定是否作为论文方法点**。

### 6.4 错题分析：核心难点定位

**T7/TA 两类时序题，模型 100% 输出 "moving"**（held-out 39/39、训练集 valid 44/44 全部如此）——它们的 41%/59% 完全是 gold 构成造成的假象，模型实际是常量作答。

**失败本质**：`发声次序 → 是哪个人 → 那一刻他的运动状态` 这条**时序-身份绑定链**在 909 题规模下没有涌现。

顺带排除了一个假警报：中间 checkpoint 在左右题上"低于随机（29.4%）"，起因是**固定偏答 × gold 分布不均衡（12:5）**，而非标注错误——我逐帧人工核验了 pilot48 与 batch2d 各自的侧向 gold，与画面一致。**由此立了一条硬规**：此后每批二选一题型答案强制 50/50 均衡。

![附图 4 · 侧向 gold 人工核验帧（pilot48 p06，第一声说话瞬间）：先发声者是绿色上衣者（source1），位于画面右侧，gold=right，与画面一致；同批 p02（gold=left）、batch2d b007（gold=left）同样逐帧核对通过](report_assets_20260824/fig4_frame_p06.jpg)

**学习梯度（论文叙事骨架）**：
```
视觉距离绑定 (98%)  →  空间侧向 (65-71%)  →  跨模态指代 (81%)  →  时序绑定 (未学会)
       容易                                                              最难
```

## 7. 论文层面的分析

### 7.1 现在已经可以主张的

1. **双模态必要性可构造、可认证**：三道闸门都有机器核验数据（B 320/320、C 51.6%、答案均衡 444/465）；
2. **当前 SOTA 全模态模型在这类题上用不上空间音频**：dual_required 上 AV−V = +0.8pp（零样本，n=125）；
3. **数据是可学的、且学习有清晰梯度**：微调后 +16.4pp，且四类题目呈现从易到难的梯度——说明数据难度是**结构化的**而非噪声。

### 7.2 现在还不能主张的（诚实清单）

1. **规模不足**：909 训练题 / 194 测试题，距论文级（训练 1.5–3 万、测试 2–3 千）差约 20 倍；
2. **多样性不足**：单房间、**单一相机视角**、单一配对类型（双人）、单一发声时刻（帧 4 固定）；
3. **时序绑定尚未涌现**：不能声称"微调可解决跨模态时序指代"，只能声称"当前规模下未涌现"；
4. **音频表征仍是折中**：训练输入用双耳折出的伪 FOA（mid/side hack，Z=X=0），**缺前后与俯仰线索**——原生 FOA 通路是提升上限的关键项（Codex 已做首个冒烟）；
5. **小样本效应**：纯音频对照仅 n=17，单点结论不可过度解读；
6. **正式准入未启动**：正式数据集分母仍为 0，35 项人工听审 + 版权清权流程未走 → 若论文要发布数据集，这是硬前置。

### 7.3 预判 reviewer 会问的问题

| 质疑 | 我们的应对 |
|---|---|
| "合成数据能代表真实吗？" | 房间来自真实扫描/商用室内资产，声学走几何传播 + 实测 HRTF；同时提供真实录制对照的讨论；卖点是**认证与反事实**，这在真实录制上做不到 |
| "会不会只是模型输入管线不支持双耳？" | 已量化区分：零样本管线折单声道的事实被明确标注，且我们的微调模型吃 4 通道 FOA，两条路径分别报告 |
| "题目是否有捷径？" | 三闸门 + 答案边际均衡 + text-only ≤ 随机 + 属性孪生翻转，全部机器核验并公开数据 |
| "为什么不用现成 benchmark？" | 现有 benchmark 的双模态必要性未认证（我们对自己 v1 的否证就是直接证据） |
| "时序题模型全错，是不是题目有问题？" | 已用同批数据的其他题型证明数据可学（98%/81%），且孪生一致性通过；给出的是**难度证据**而非缺陷 |

| 4 | **正式准入流程什么时候启动**（35 项人工听审 + 版权清权）？谁来听审？ | 这是数据集能否随论文发布的硬前置，不能压到投稿前 | 倾向 **9 月中启动**，按批次滚动听审（每批 48 点抽样） |
| 5 | **基线范围**：闭源 API（GPT-4o / Gemini）是否入表？ | 目前只有开源线（Qwen2.5-Omni、Qwen3-VL、SO-7B）；闭源多为单声道音频通道，会混淆"模型不行"与"通道不支持" | 倾向**入表但单列**，并明确标注音频通道能力 |
| 6 | **方法点是否继续押时间对齐 RoPE**？还是转向显式监督（DoA 回归头 / 事件-帧对齐损失）？ | 909 题规模下时间对齐无收益，但也未被证伪（模型还没进入"用时序"阶段） | 倾向**3k 规模复测一次**；同时并行试一个显式 DoA 监督头（成本小） |
| 7 | **人格化 / 说话人身份线索**（personalization）要不要做成本次投稿的一个 setting？ | 之前讨论时您提过；现在只在 manifest 里留了 speaker id 接口 | 倾向**留接口不做 setting**，除非主集提前完成 |
| 8 | **评测协议**：主指标用 AV−V 差值 + 按认证等级分层，够不够？是否要引入解耦评估（区分"感知失败"与"推理失败"）？ | 现在的报数方式是三条件 acc + 差值 | 想听您的意见，倾向再加一层**按空间线索强度分桶**的报数 |
| 9 | **拒答题怎么算分**：当作一类答案，还是单独报 refusal 的精确率/召回？ | 配额已定 10–15%，实现前需定评分口径 | 倾向**双报**：主表算一类答案，附表单独报 refusal |
| 10 | **数值 DoA 的评分带**：现在 ±15°/±30° 是占位，是否沿用，还是按 BAT 那样离散成 8 扇区？ | 影响 T5 题型的实现与可比性 | 倾向**同时给**：连续误差 + 8 扇区离散命中，便于与 BAT 类工作对齐 |

## 附录 B · 术语

- **foaish**：由双耳信号折出的伪一阶 Ambisonics（W=(L+R)/2, Y=(L−R)/2, Z=X=0），只有左右信息，缺前后与俯仰；
- **held-out**：训练完全未见的测试集（本轮为 pilot48，与零样本基线同题，可直接对比）；
- **EM**：exact match，生成答案与标准答案严格一致的比例；
- **research_only / episode_counted=false**：全部产物的合规标记，正式数据集计数保持 0。
