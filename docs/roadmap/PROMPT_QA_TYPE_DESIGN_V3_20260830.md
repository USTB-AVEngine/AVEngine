## 你在做什么项目(一分钟)

我们在做一个投 CVPR 2027 的 benchmark:室内仿真场景里的"空间音视频问答"。
模型看一段第一人称视频、听对应的双耳音频,回答跨模态问题(用一个模态指代目标,
用另一个模态提问)。两个卖点:

1. **数值方位题**:直接问"发声的东西在你哪个方向",答案是角度,按 ±15°/±30°
   的容差带计分——别家都是"左边还是右边"的选择题,我们能出数值题,因为——
2. **每道题带引擎证书**:场景、声学、轨迹全部出自物理仿真,答案由引擎记录的
   真值推导,证书可机器复验。对比对象 JAEGER 的公开数据没有混响;我们的房间
   声学(混响、遮挡)是真实仿真的。

## 铁规矩(已定,不要重新讨论)

1. 题目是从引擎记录的事实里**挖**出来再**发证书**的。人只设计题型模板,
   永远不手写单题——手写的题没有证书。
2. 出题公理(v2 已定稿):问句禁止出现场景内唯一存在的类别名(歧义压力);
   每题过单模态可答闸门;先写自由形式的标准答案再机械地选项化;干扰项必须
   在数据集中真实出现过;负样本是一等公民(静音在场/出画发声/多实例单发声);
   真值全部引擎签发,人工只做抽验。
3. 三道认证闸门已实证能跑:闸门 A 音频必要(换音频孪生,答案必须翻转)、
   闸门 B 视觉必要(换外观孪生,上一批 320/320 全过)、闸门 C 纯文本作答
   必须≤随机线(上一批 51.6%,过)。
4. 产能背景:约 1,400 间人工筛过的房间 × 每间约 30 条声源轨迹 × 每条约 4.7 题
   → 容量 2.5 万到 19 万题,而训练只需要 3 千量级。**量不是瓶颈,题型质量才是。**
5. 交付文风:说人话。完整句子,术语第一次出现就解释,不写电报腔
   (owner 的硬性要求,有前科)。

## 你要交付什么

一份《题型设计全案 v3》,写到 `docs/roadmap/QA_TYPE_DESIGN_V3_<日期>.md`,
push 到 main,并发布一页 artifact 方便 owner 和导师逐条批注。内容五块:

1. **模型能力调研(重点,要查 2025–2026 的最新工作,不要只靠记忆)**:
   哪些现役模型能回答"锚定在某个时刻"的问题("第二声猫叫的时候…""第 3 秒时…")
   ——Gemini 2.5 系、GPT-4o/实时系、Qwen2.5-Omni、各时间敏感 video-LLM。
   现有时间锚定类 benchmark(DAVE、TraceAV 这些)的题是怎么措辞、真值怎么标、
   怎么判分的。结论要落到:我们的论文该拿哪些模型当基线、时刻锚定题照谁的
   句式出。
2. **五个新题向的设计**,每个都带四件套(例题 / 引擎真值从哪来 / 防作弊闸门 /
   判分协议):
   - a. **时刻锚定题**:"第 N 声"和"第 t 秒"两种锚定方式都要设计;
   - b. **说话内容题**:"第一个说话的人说了什么"——真值是带逐字转写的语音素材
     (素材线同学 B 在收,转写字段规范由这份全案定);
   - c. **开放式题**:答案不设选项,What 开头的问法;判分分三级:数值容差带 /
     结构化字段核对 / LLM 当裁判,各自适用哪类题要写清;
   - d. **推理题**:对标"数学推理型 benchmark"的形态。我们的独门优势:推理链
     每一步引擎都能签真值(AURA、OmniVideoBench 的推理轨迹靠人标,我们不用),
     设计时把这个优势用足;
   - e. **个性化 / 时空记忆题**:受控实例跨时段重现,比如"刚才在厨房叫的那只猫
     现在在哪"——可以设计多段式 episode,把细粒度外观/音色绑定到个体上。
3. **owner 亲自点名的漏洞,必须堵**:"第一声说话时,说话人离相机更近还是更远"
   这类题,双耳音频的响度和混响本身就带距离信息,不看画面也能答。
   全案里要把"每题三探针"(纯视觉/纯音频/纯文本各答一遍)定为机器流程:
   纯音频能答对的题自动降级进"音频充分对照组",永远不进主集。
4. **20 格矩阵台账**:指代模态(外观/声音/空间/时间锚)×提问模态(外观/声音/
   空间/时序/数量)逐格标注:已实现 / 已设计未实现 / 本次新增 / 故意不做+理由。
   现状:v2 设计了 10 类,挖矿器只实现了 5 类(全是二选一),**卖点数值方位题
   T5 还没实现**;时序题 T7/TA 上一轮所有模型都在常量作答,说明题型本身时序
   信号太弱,要在这次重设计里救回来。
5. **落地切分**:哪些题型进 CVPR 主表、哪些排 v2;每类的工程依赖
   (要不要新素材、新采样形态、新判分器),给出实现顺序建议。
