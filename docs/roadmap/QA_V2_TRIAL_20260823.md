## 1. 试验设置

在 intermittent-200 fact tables 上做零渲染去物种化出题，4 个试验题类：

| 试验类 | 对应 v2 题类 | 题干（去物种化指代） | 预期 |
| --- | --- | --- | --- |
| TQ-A | T7（R-A→Q-V） | 最先发声的那只动物，发声开始时在走动还是静止？ | 双模态候选 |
| TQ-B | T4（R-A→Q-S） | 最先发声的那只动物在画面左侧还是右侧？ | 音频充分对照组 |
| TQ-C | T7（R-T→Q-V） | 最后一次发声期间，发声者在走动还是静止？ | 双模态候选 |
| TQ-D | T2（R-A→Q-V） | 发出第一声叫声的动物毛色是什么？ | **故意生成，验证捷径闸门** |

规则闸门：G-identity-margin（首声间隔 ≥0.3s）、G-differential（答案必须
随指代对象不同而不同）、G-visible（指代对象事件窗内在视锥）、G-stable
（事件窗内状态恒定）、G-azimuth-margin（|方位角| ≥10°）、
G-shortcut-dataset（数据集级捷径检查）。

## 2. 结果

**产率：200 集 → 747 条原始候选 → 38 条全闸门通过 → 答案均衡后 24 条（12%）。**

拒因分布（每类约 200 条候选）：

| 拒因 | TQ-A | TQ-B | TQ-C | 含义 |
| --- | --- | --- | --- | --- |
| G-visible | 132 | 132 | 133 | **约 2/3 的集：指代对象在事件窗内出画**——轨迹生成时无"发声时在画面内"约束 |
| G-differential | 98 | 109 | 98 | **约一半的集：两源同动静/同侧**——both_moving/static_static 配额是生成侧定的，与出题无关 |
| G-identity-margin | 69 | 69 | 107 | **约 1/3 的集：双源首/末声间隔 <0.3s**——事件窗随机撒，没有可分性约束 |
| G-azimuth-margin | — | 24 | — | 首声时刻方位角过中线 |
| G-shortcut-dataset | — | — | — | **TQ-D 33 条全部正确拒掉**（coat↔物种双射，音频即可定毛色）——v1 死穴被闸门抓住 ✓ |

三个主要拒因没有一个是"题出得不好"，全是"视频生成时没带题的要求"。
另：TQ-B 通过 12 条但左右 11:1 失衡（方位角分布偏科的直接后果），均衡
后仅剩 2 条。

**闸门 C（question-only 盲猜，Qwen2.5-Omni-7B，24 题）：12/24 = 50.0%
= 恰好 chance**（TQ-A 8/16、TQ-B 1/2、TQ-C 3/6）。细节：模型 22/24 恒
答 B——纯文本下策略退化为常数猜测，被答案均衡精确压到 chance。对照
v1 pilot text_only 39% > random 34%：**去物种化改写消除了文本先验 ✓**。
（n=24 为机器验证规模；闸门 C 在 v2 里是集合级闸门，逐题版留给正式批。）

## 3. 结论：反向拟合（题型引导生成）

v2 生产管线定型为：

```
题型配额（T1–T9 × 难度桶 × 答案均衡）
  → 编译为场景约束（运动差分 / 事件间隔 / 可见窗 / 方位桶 / 属性组合）
  → Studio sweep 逐点生成（约束即真值，产率按构造接近 100%）
  → 挖题器 + 三闸门事后复核（审计引擎输出，不再承担筛选）
```

挖题式若要 1000 条合格题需 ~8000 集（12% 产率），GPU 成本 ×8；反向拟
合把闸门条件前置为生成约束，本次写的挖题器与闸门代码在复核层原样复用。

## 4. 32 点同物种双源小批配额草案（待 owner 批准后动 GPU）

目的：在同物种双源场景上验证 T2/T3/T9 的指代歧义压力 + 闸门 B（属性孪
生）。载体 apartment_0000，两实例同物种、恰好一个受控属性不同。

| 轴 | 分配（32 点） |
| --- | --- |
| 实例对 | two humans（top_color 两两取自 blue/green/burgundy）24 点；若两犬不同 coat 资产已注册则 8 点给 two dogs，否则 32 点全 humans |
| 运动差分 | 一动一静 24 点（12 点 source1 动 + 12 点 source2 动，供 TQ-A/C 类）；both_moving 8 点（作 G-differential 退化对照与 T9 比较题载体） |
| 事件程序 | 间歇发声，双源首声错开 ≥0.5s，每源 ≥2 事件，事件窗完全落在该源可见窗内 |
| 可见性 | 24 点：指代对象事件窗内全程在视锥；8 点：**故意在发声窗内出画**（off-screen 负例/refusal 坑位） |
| 方位桶 | 首声方位角按 8 扇区均匀分派，**侧向 ±60–105° 至少 8 点**（补 v1 空档）；左右按构造均衡 |
| 属性孪生（闸门 B） | 16 点配孪生链：同轨迹同事件、仅交换两实例属性（换色），验证"答案随属性翻转" |
| 说话内容（T3 接口） | human 点绑定已清权语音资产（CREMA-D 系），manifest 写入说话人 ID 字段（personalization (b) 档接口，per owner 决议） |

规模与成本：32 主链 + 16 孪生 = 48 条链 × 5–15 min 串行 GPU ≈ **4–12 小时**。

预期产出：每点支撑 T2/T3/T9 + 运动/时序指代题约 6–10 条认证题
→ **约 200–300 条认证题**（对照：挖题式 200 集仅得 24 条）。
