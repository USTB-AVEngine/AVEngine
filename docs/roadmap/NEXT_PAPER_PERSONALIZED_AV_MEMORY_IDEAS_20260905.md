# 下一篇论文 ideas：个性化视听感知与时空记忆

2026-09-05。根据用户明确决定，从当前房间/本篇 QA 工作中分离保存。本文是后续研究想法，不是当前实现承诺、资产能力清单或已验证结果；不自动启动新人物资产、语音生成、记忆系统或新题型开发。

**为什么保留这条线。**

当前工作提供可控房间、人物/听者位置、双耳音频、可见性和短片段问答。后续可以研究一个模型能否把“看见谁、听到谁、何时在哪里发生了什么、这个人曾明确表达什么”联系起来，并在后续场景中正确使用和更新。这比仅增加问句数量更接近个性化的视听时空记忆问题。

需要分别证明细粒度感知、身份关联、事件记忆和偏好更新。一个内部 entity_id 只保证生成器知道谁是谁，不保证输入足以让人或模型认出；多片段也不自动叫长期记忆，应明确时间跨度和干扰量。

**两篇参考论文与我们自己的延伸。**

- [Hear you are: Teaching LLMs Spatial Reasoning with Vision and Spatial Sound](https://openaccess.thecvf.com/content/CVPR2026/papers/Ryu_Hear_you_are_Teaching_LLMs_Spatial_Reasoning_with_Vision_and_CVPR_2026_paper.pdf)：借鉴同类目标的空间消歧、语义匹配不可靠时依靠双耳空间信息的设计。其单图/短音频空间 QA 不是个性化或跨段记忆验证。
- [VoxParadox](https://arxiv.org/pdf/2605.27772)：借鉴台词与实际发声特征不一致的控制，检验模型是否追随台词而忽视音高、语速、语调或说话人线索。它研究副语言感知；将这些信号与人物历史、空间和偏好联系起来，是这里保留的延伸设想。

已阅读正文、关键图表与相关附录。不能仅凭这两篇论文宣布后续主题具有新颖性；下一篇真正立项时还需补跨片段身份、个性化和视听记忆相关工作。

**当前资产边界。**

本轮已接入的四个 Rocketbox 人物能使用受控的蓝/粉/绿/白衣色、人物身份、姿态和空间位置；VCTK 提供已绑定的说话人录音与逐字内容。眼镜、手环、衣纹、个人偏好、持续声纹重识别和跨段记忆均没有在这条链路里被登记并验证。

因此，下面保留的“戴眼镜”“红手环”“细条纹”等是未来资产条件，不是当前人物数据集已支持的类别。不应要求本篇为这些想法临时扩充人物资产。后续即使不新增这些细节，也可以先用现有衣色、位置、声音片段和清楚的历史线索研究记忆；但仍须避免把衣色固定映射到身份造成捷径。

**保留的场景和例题。**

| 方向 | 生活场景与例题 | 需要先补足的条件 |
|---|---|---|
| 同类目标空间消歧 | 几人在餐桌旁静坐：“刚才说话的是左边戴眼镜的人，还是右边戴眼镜的人？” | 眼镜例需要新受控标签与可见资产。现有资产可先用当前可辨衣色/位置表达一般绑定问题，但不能把它称作眼镜细粒度能力 |
| 细音频→细视觉 | 几人说同一句：“说得最快的人上衣是什么花纹？”→ 细条纹 | 衣纹资产与标注；受控语速；经过房间混响后仍可辨的最终音轨 |
| 细视觉→声音变化 | “戴红手环的人第二次说话比第一次音高更高还是更低？”→ 更高 | 手环可见资产；两次可关联语音及 F0 差异；时间锚 |
| 台词与声学冲突 | 用下降语调说“我的语调正在上扬”；问句尾音调怎样变化 → 下降 | 可控音频制作与重听验证；不能拿台词内容作为声学真值 |
| 说完话后的静默追踪 | 厨房的人提醒开饭后走到客厅；“刚才提醒开饭的人最后在哪？”→ 客厅 | 可辨身份和实际轨迹；静默查询窗；避免持续脚步等侧信道使音频单独泄漏答案。该短时形式可衔接现有错时题，但不自动当长期记忆 |
| 跨段人物/声音关联 | 第 1 段看到并听到人物，第 2 段只听一句新话；“这是谁？”→ 前段靠窗的人 | 稳定而可观测的跨段身份；不同台词/房间混响；不能直接把 source_id 给被评模型 |
| 明确个人偏好与更新 | 早餐说喜欢窗边，午后改说今天想坐靠墙；“按他最后表达的偏好，应指向哪张椅子？”→ 靠墙椅 | 明确偏好话语、人物绑定、时间与更新；可靠椅子语义；不从外貌推测偏好，不需要实际拉椅子动作 |
| 历史时空与证据来源 | 上午在书桌旁说杯子在厨房，后来在餐桌旁改口说在餐厅；“他最后在哪里修改了杯子位置的说法？”→ 餐桌旁 | 人、时间、位置、陈述内容和更新；分开“说法”“物体真实位置”和“模型看到的证据” |
| 观测不足的记忆回答 | 只看到某人离开厨房门口，没有后续观测；“他现在确定在哪？”→ 无法确定，最后在厨房门口 | 世界真值与允许观察的历史分开；提供准确的最后观测，不让评测要求不可见未来信息 |

以上是 idea 清单。眼镜/手环/花纹题保留，但不进入当前可落地任务表；当前人物资产不扩展也能做的一部分问题，同样需后续独立设计采样和评测，不能直接宣布已经实现。

**后续实现可以怎样保持 AVEngine 的统一规划。**

沿用 Episode、相机/听者规划、声音事件、像素事实和已有问答求值。故事配置串联多个 Episode，普通稳定实体主键维持故事内身份，普通事件记录保存发生时间、地点和可观测区间；明确偏好记录生效与被纠正时间。先定义观察截止时刻，再产生问题，避免读到未来信息。无需默认引入新的 hash、冻结 contract、baseline 文件或发布 gate。

生产相机与听者轨迹仍归 AVEngine；房间作者只提供几何和语义。所有房间可以复用人体姿态和已有行走；需要椅子、沙发或桌子的题目，只在具备可靠对应语义的房间编排。扫描房间没有家具标注时，不承诺相同家具级操作。

不需要抓取、开门、拉椅子或坐下过渡。人物已经坐在椅子上、站在厨房、在房间之间行走，以及可观察的语音/历史事件，就足以组织这些研究原型。

**后续应验证什么。**

- 当前片段相同而历史不同，答案随历史改变；对比完整历史、关键历史缺失、时间顺序打乱、人物历史互换、偏好过期等条件。这样才能测历史是否真的被用到。
- 同一句话改变声音特征、同一声音改变台词；故事内身份保持一致，故事之间重新分配衣色和声音绑定；模型不能只记住蓝衣等于某一个录音。
- 细粒度真值必须能在最终 UE 像素与双耳音轨中被观察。TTS/资产元数据是生成真值来源，不是可答性证明；对模糊语气和身份匹配需实际听辨检查。
- 响度问题先说清是“听者收到的响度”还是“说话人的发声强度”。距离、材料与混响会改变前者，不能把同一个 dry gain 当成两种答案。
- 利用现有缺失模态评测分别报告感知、跨模态绑定、时间和记忆贡献；不要求所有题都同时依赖全部模态。只数事件、即时左右等也可保留为清楚标注的对照。
- 人物、录音、房间和真实/合成来源的切分必须有意义；同一段干声换房间后放入训练和测试，不足以证明跨内容泛化。报告跨度、间隔和干扰事件量，不用片段变长代替“长期”定义。
