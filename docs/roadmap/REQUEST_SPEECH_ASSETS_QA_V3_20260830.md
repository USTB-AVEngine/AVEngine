# 语音素材与人物资产需求单(题型 v3 → 素材线,20260830)

> 给素材线同学的一页需求。背景一句话:题型全案 v3(仓库
> `docs/roadmap/QA_TYPE_DESIGN_V3_20260830.md`)里有两类"说话内容"题
> ——"穿蓝上衣的人说了什么"和"说'过来'的人穿什么颜色"——它们能不能赶上
> 主投稿,取决于下面两块素材什么时候到位。有问题直接找 owner 或在这页
> 上批注。

## 需求一:语音素材(带逐字转写)

**场景长什么样**:同一个片段里有**四个人都在画面里,每人恰好说一句话**
(为什么每人只说一句:说两句会让"他说了什么"出现两个正确答案,题就废了
——这是设计定稿,不是建议)。

**每条语音素材登记时要带四个字段**:

1. **逐字文本**(transcript_text):这句话逐字写下来,标点随意但字要准
   (判分按字错率比对,转写错一个字就冤枉模型一次);
2. **语言**(language):中文/英文/其他;
3. **句内起止点**:这句话在音频文件里从第几秒到第几秒;
4. **说话人声音编号**(speaker_voice_id):同一个人的声音用同一个编号,
   不同人不同编号。

**几条采集要求**:

- **每个声音编号至少 8 句,单条时长 0.8–1.5 秒**(时长差太大,模型光听
  长短就能排除选项)。**时长硬规则(codex 复核后定稿)**:我们的片段一共
  5 秒,四个人各说一句且不重叠——所以采样侧组题时,**所选四句的总时长
  加上句间间隔必须 ≤5 秒;凑不进去就拒绝这个组合、换四句重选,不自动
  重叠、不自动截断**。之前写的"单条 1–3 秒"塞不进这笔账,作废。素材侧
  只需按单条 0.8–1.5 秒收,组合规则由采样侧执行;
- **说话人切分**:同一个声音编号的素材将来只会进训练集或只进评测集,
  不会两边都用(登记时不用你分,但每句都要把声音编号标对,分集靠它);
- 内容不限,日常短句就行("该吃饭了""过来""外面下雨了"这种);四个人
  的句子内容要互不相同;
- **权利登记照仓库现有规则**(`schemas/m6_sound_asset_registry_v1.schema.json`
  的 provenance 四字段):来源(origin)、许可证(license)、权利状态
  (rights_status)、权利证据哈希。**四个字段本身都不能省**;许可证不
  知道时,license 这一项写 `null`(JSON 的空值,不是删掉这一行),同时
  rights_status 填 `unresolved`——"明确写了不知道"和"忘了填"在登记里是
  两回事。网上下的顺手把网址填进来源字段;**研究阶段不需要先搞清许可证
  才能用**,只有将来真正进正式数据集/公开发布的那部分才需要补权利核验
  ——这是 owner 已拍板的分层规则,不用紧张。

## 需求二:第四种受控衣色 + 四人同场

**现状**:人物资产的受控上衣颜色只有三种(蓝、绿、酒红)。

**要什么**:

1. **加第四种受控衣色**(建议黑色或亮黄色,跟室内场景对比度好、跟现有
   三色区分度大;Rocketbox 换色管线是现成的,预计工程量小);
2. **采样形态支持同场四人**(四种衣色各一人),四个人在画面中的方位
   要拉得开——两两之间的方位角间隔建议**至少 25°**(声音归属靠双耳方向
   对画面位置,人挤在一起就绑定不了;这个数值是初步建议,以容差带校准
   结果为准,校准材料在 `docs/roadmap/TOLERANCE_CALIBRATION_OPTIONS_
   20260830.md`)。

## 优先级

这两类题在全案里标的是"主集候选(素材线依赖)":素材赶得上,pilot 就
带上它们;赶不上就顺延、不进主投稿(不影响其他题型推进)。所以**不设
硬截止**,但越早到位,说话内容题进主投稿的机会越大。
