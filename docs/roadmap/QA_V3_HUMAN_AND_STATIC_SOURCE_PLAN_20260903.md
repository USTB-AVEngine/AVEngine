## 2. 顺序

### 阶段 H0：注册表补齐（0.5–1 天，不动生成器）

1. 每个资产补 `body_m`：身高、体长、体宽（狗 0.5/0.8/0.4，人 1.7/0.5/0.5，占位，可由 Pixel3D 包围盒校）。
2. 每个资产补 `appearance_label` 与 `referring_expression`（狗 = 毛色词，人 = 上衣颜色词）。
3. 第四种受控上衣颜色：card13/card14 要 4 种，现在 3 种；改色走现有 Blender 资产管线。
   不想等的话，先只跑不需要 4 种的题型。

### 阶段 H1：两个人的题（生成器改动 1–2 天 + canary）

owner 已定起手：**两个改色人物、同一把声音、走路动作**，与两只狗完全平行。

1. 题型配置加 `asset_policy`（见资产政策方案）：card1F/1B、card7、card9、card5R、card6R、card4R、card2/3/5/6/10
   声明 `same_family_distinct_instances`、`allowed_families: ["dog", "human"]`、指代词按族取。
2. 生成器：`build_cell_plan` 的配对从政策取，`COAT_WORDS` 换成资产的 `appearance_label`，MCQ 选项从指代词生成。
3. 音频：人的题两个角色共用那一条人声素材（`voice.shared_clip_across_roles: true`），身份只靠外观区分；
   题面里的"狗"换成"人"由指代词驱动，不能再写死。
4. 两房 canary：核心题型各 6 格，用人跑一遍；card1 候选跑像素真值。
5. 三项对照要重做，因为都是狗上标定的：
   - 净空表的目标带换 1.7 m：人的目标带在画面中段，半高家具挡不住它，0.2 的阈值大概率要另定；
     用人的像素真值重跑"机位堵死"的阳性对照。
   - 预测可见性对人的逐帧对照（同一工具，身高体宽换成人）。
   - 像素分档边界 0.5 / 0.2 对人是否合适，看分布。
6. 人类校准包里放进人的题，但要等狗的 v4 先出。

### 阶段 S1：静态声源（音响）（资产 1 天 + 生成器 1 天 + canary）

1. 资产：做一个音响的网格并注册为 `family: speaker`，`motion: must_be_still`，`voice.identity_coupled: false`
   （什么声音都能放）。放在地上还是桌上要定：放桌上需要"桌面可放置"信息，第一批只放地上。
2. 摆放：静止声源就是零位移路线。Kujiale 有 200 条静止路线可直接用；Apartment 没有，
   要从可走栅格抽站点（与路线合成方案共用栅格）。
3. 适用题型：`any_single_source` 的 card8（首叫时间带）、card15b（事件计数）；
   以及以后的"声音从哪来"类混族题，题面只能说"声音"不能说"狗"。
4. **不适用**：card6R 这类"谁在动谁没动"的题不能拿音响当静止角色，外观就把答案泄了；
   资产政策里要写成同族配对才允许。
5. 音频：音响播狗叫、人声或测试信号；fact 记"声音内容与身份脱钩"，探针要专门查
   "只听声音能不能猜到是音响"。
6. canary：card8 用"一只狗 + 一个音响"与"两个音响"各跑 6 格，看首叫间隔链与 Gate A 翻转是否照常成立。

### 阶段 M1：猫与混族（等前两阶段）

注册表有 2 只猫但没有猫叫素材；混族题（狗 + 猫）要先补声音素材，再按
`mixed_families_voice_decoupled` 或 `same_family_distinct_instances` 声明。本轮不排期。

## 3. 验证原则

每一族都走同一条链：几何求解 → 时间线 → 像素真值 → join → 对照；三个标定过的东西
（机位堵死阈值、预测可见性、分档边界）换族就重新对照，不沿用狗的数字。
