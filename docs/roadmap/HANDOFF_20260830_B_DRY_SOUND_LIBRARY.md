# 给同学 B 的说明:声音素材(2026-09-01 更新)

你负责的是这个项目的**声音素材库**:各种物体发出的声音(狗叫、门铃、微波炉、
水龙头),以及人说话的录音。我们把这些声音"放"进虚拟房间里的物体上,让引擎算
出它传到耳朵里是什么样,再用来出题考模型。

**重要变化**:原来说的"手工去网上收集"作废了。服务器上本来就有现成的大型素材库,
采集全部由脚本完成,你不用下载任何东西。你的活变成两件:**核对一张对照表**、
**抽听确认没串味**。

## 先看现状

素材库现在有 **1200 个文件**,覆盖 37 个事件类,每类中位 20 条;另外有 **600 条
英语人声**,每条都带精确的文字稿。这些都是脚本采集的,已经过质检和格式处理。

打开网页看:先建隧道(把尖括号换成你自己的服务器登录方式)

```
ssh -L 8765:127.0.0.1:8765 <你的服务器>
```

浏览器开 http://localhost:8765 ,点页面最底下的"声音素材库"。每条素材旁边有
机器质检的结论:绿章"机器质检 ✓"没问题,黄的"有提醒"能用但最好换,红的"不可用"
必须换。机器会用大白话说哪里不对。

## 你的第一件活:核对对照表

文件在仓库里:**`examples/assets/sound_harvest_map_v1.json`**
(GitHub: https://github.com/USTB-AVEngine/AVEngine/blob/main/examples/assets/sound_harvest_map_v1.json )

37 行,每行是"我们的类名 → 从 FSD50K 的哪个标签里抓",后面跟一句注意事项。
这张表是我一条条手写的,**必须有人核**——自动按名字匹配会出洋相,我试的时候
它把"微波炉提示音"配成了"乌鸦叫"、把"火焰声"配成了"火警报警器"。

重点看这几行(我在 `note_zh` 里标了要抽听的):

- `microwave_beep` 和 `microwave_hum` 在 FSD50K 里是**同一个标签**,提示音和运行
  嗡声混在一起,得靠人分开;
- `Alarm` 是个大类,`alarm_beep` / `fire_alarm` / `smoke_alarm` 都从里面抓,
  可能混进警笛;
- `Cat` 里可能有呼噜声,`Dog` 里可能有喘气,都不是我们要的"叫";
- `Crack`(断裂单响)和 `Crackle`(持续噼啪)是两回事。

发现错的直接改这个文件,或者把行号发出来。改完重跑采集脚本会自动补齐差额,
不会重复抓已有的。

## 你的第二件活:抽听

每类点开两三条听一下,确认没串味(比如"水龙头"里混进"抽水马桶")。
听着不对的,把路径发出来。

## 还缺的类(需要你想办法)

有 12 个类在干净的素材池里凑不够 20 条,现在是这个数:

| 类 | 现有 | 说明 |
|---|---|---|
| dial_tone(拨号音) | 3 | 池子里本来就只有 7 条 |
| doorbell(门铃) | 4 | 和 ding_dong 抢同一批素材,大部分归到那边了 |
| microwave_hum(微波炉嗡声) | 8 | 要从 microwave_beep 那批里人工分出来 |
| telephone_dialing_dtmf(按键音) | 9 | 池子里只有 7 条 |
| buzzer(蜂鸣器) | 10 | 池子里只有 9 条 |
| doorbell_chime、busy_signal、smoke_alarm | 10–12 | 同上,池子薄 |

这几类都是"一个设备一种声音",本来花样就不多。三条路子,你选:一是把目标从
20 降到 10(我觉得够用,拆训练和考试也够);二是去 FSD50K 的多标签池里补
(那里面一条录音挂好几个标签,可能混着别的声音,得抽听);三是自己录几条
(手机、门铃、微波炉这些身边就有)。

## 人声(新增,已经做好了)

600 条英语人声,来自 VCTK 语音库。选它是因为**它是在半消声室里录的**——天然
没有回声,正合我们的需要(回声必须由引擎来加,素材自带的话会叠两遍)。

每条素材的旁车 json 里多了这些字段:

```json
{
  "event_classes": ["speech_playback"],
  "transcript": "Please call Stella.",
  "speaker_id": "p225",
  "gender": "F",
  "accent": "English",
  "split": "eval",
  "controlled_content": true,
  "language": "en"
}
```

几个设计上的说明,你了解一下就行:

- **说话人分成两组,互不重叠**:训练用 16 人,考试用 8 人,男女各半。同一个人
  绝不会同时出现在两边——不然模型听过这个嗓音,考试等于开卷。
- **有一批"内容受控"的素材**(277 条,`controlled_content: true`):VCTK 每个人
  开头都念同一段文字,所以我们有了"内容完全一样、只有嗓音不同"的材料。问
  "是哪个人在说话"时,模型没法靠内容作弊。
- **转写就是标准答案**:以后会有"刚才说话的人说了什么"这类题,答案直接用
  `transcript` 字段。
- 目前只做英语。普通话素材(AISHELL)服务器上也有,以后要的话再加。

## 三个命令(需要时用)

在仓库根目录下跑,**注意用项目自带的 Python,系统的 python3 缺依赖**:

```bash
P=/data/jzy/miniconda3/envs/avengine-habitat-runtime/bin/python
$P tools/assets/harvest_fsd50k_clips.py    # 按对照表采集音效(改完表重跑,自动补差额)
$P tools/assets/qc_sound_library.py        # 质检:每条量一遍,结论显示在网页上
$P tools/assets/prepare_sound_library.py   # 格式处理:转 16 kHz 单声道等
```

加 `--dry-run` 可以先演习一遍看会抓多少、不写盘。人声的采集脚本是
`tools/assets/harvest_vctk_speech.py`,已经跑过一次了,一般不用再跑。

**清洗完全不用你管**。去直流、抗混叠重采样、剪首尾静音、峰值归一,脚本统一处理,
处理后的副本放在另一个目录,**你的原始文件一个字节都不会被改**。每条改了什么
都记在清单里可查。质检判红的会被自动跳过——处理不能修复失真,坏素材只能换。

## 两条硬规矩

1. **同一段声音不要复制到多个文件夹**。一条录音可以同时算好几个类(闹钟那声"嘀"
   既是 `alarm_beep` 也是 `alarm_clock`),正确做法是只放一份,在旁车的
   `event_classes` 里把几个类都写上。复制成两份,系统会当成两段不同的声音,
   可能把一模一样的音频同时给房间里的两个物体,那道题就没答案了。网页上会用
   黄字标出重复的。
2. **红章的必须换掉,别修**。现在库里有 17 条是红的,原因写在每条旁边。
