# 房间范围与可行域判断规则及操作细则

> **文档关系：** 本文件将 ROOM_SCREENING_PLAN.md 转成逐项操作规则；冲突时以 Plan 为准。本文件不另设面积、颜色、高度或路线门槛。
> **适用范围：** 已下载的 181 栋 HM3D 场景。本阶段只形成经核验房间范围内的几何筛选结果，不证明人物、摄像机、物品摆放或声学任务适用性。
> **当前执行口径（2026-10-07）：** 主面积为同层语义地面投影并集减已识别阻挡物占地并集；真实同层地面补片须先核验后按多边形并集加入。探针只作遗漏/碰撞路径辅助，不以探针栅格面积替换、增减主面积。10 m²为当前项目筛选下限；范围未决且可能改变阈值结果时保持范围待核。完整运行统计见 [运行摘要](EXECUTION_SUMMARY_20261007.md)。

## 1. 每个房间分别记录什么

每个对象/楼层分别记录四项，不合成一个“能不能用”字段：

1. **范围来源、核验状态与分析类别：** 分别保存 `scope_source`、`scope_status`、`scope_analysis_class`。来源记录语义地面成员面、人工多边形、网页蓝框 AABB 或无；状态记录 candidate、verified、proxy_only 或 unresolved；分析类别可为 semantic_region_verified、manual_scope、bbox_proxy_only、unresolved，流程中尚未终核时为 pending_verification。网页蓝框单独留作候选字段，不默认视为房间范围。
2. **几何标签：** present、absent、uncertain；资料/场景/navmesh 无法判读时为 unassessable。
3. **助手批量结果与负责人抽查结果：** 分开保存。助手按统一规则处理全量；负责人只抽查少量代表/高风险样本，不逐项标注。仅实际看过的样本填写 `owner_final_label` 与 `owner_correction_reason`；其余保留 `assistant_suggestion`、证据、置信/异常状态，不伪记成人工确认。
4. **项目处理建议：** 保留、舍弃候选、裁剪、存疑。房间类别另记，不代替几何标签。

**处理方式：全量自动计算，负责人抽样校验。** 助手先对 181 栋所有对象运行同一套范围、地面、家具和楼层规则；负责人只看少量代表样本及机器识别的高风险类型。抽查反馈用于修订规则后批量重跑所有匹配对象，不把机器异常表逐项交给负责人。无法按既定证据自动判定的对象标 `unresolved` 或 `review`，由助手汇总成少数原因类别；不通过反复要求负责人逐房确认来制造“已核实”状态。抽样证据不足时，关闭对应自动筛除/阈值结论，不影响助手继续产出带异常标记的全量几何结果。

语义物体标签缺失不自动判存疑。只有蓝框或截图像素而没有可核验的语义成员面几何/人工范围时，不从截图猜主范围；助手可依据 Habitat 场景证据生成 `manual_scope` 候选，只有边界证据足够清楚才纳入；否则标 `unresolved`，由助手集中报告而不是逐房转交负责人。bbox_proxy_only 只留作单独的矩形代理结果，不进入主面积筛选。

## 2. 房间范围核验与楼层

### 2.1 语义区域几何与候选蓝框

网页蓝框是 HM3D 语义区域的轴对齐几何包围盒候选，不是精确墙线，也不能证明 room_id/region_id 标注本身和目标物理房间完全一致。当前房间清单生成逻辑按同一 `region_id` 成员三角面的坐标极值生成 `bbox_xz_m`；因此它只表示该组被标注面片的外包矩形。矩形与邻室/走廊相交可能只是外包形状过宽，不能仅凭这一点判断房间标注越界。

按以下顺序确定主范围；蓝框不是默认主范围，region 标注和其成员面也不能未经核验直接视为真实房间边界：

1. 核对网页房间编号、清单 `region_id` 与语义标注成员面映射。
2. 如果能读取成员面几何，提取目标 region 的地面类面片，投影 X/Z 并集作为语义候选范围；同时叠加蓝框、navmesh 和原始 Habitat RGB，检查 room_id↔region_id 是否相符、地面范围是否覆盖目标主体、是否有扫描/标注缺失。蓝框跨入邻室/走廊可能只是轴对齐外包矩形过宽；只有实际成员面跨界或其他场景证据才作为区域错配线索。
3. 助手依据映射表、语义地面覆盖、楼层一致性和 RGB/场景几何抽查规则批量核对 room_id↔region_id。证据充分的对象记 `scope_source=semantic_region_ground_faces`、`scope_status=verified`、`scope_analysis_class=semantic_region_verified`，并记 `scope_verification_method=assistant_auto`；该状态表示达到已记录的项目操作规则，不宣称真实墙线真值。负责人只抽查少量代表/高风险对象。
4. 若语义成员面几何缺失/不完整或映射不符，但 Habitat 中墙、门洞等结构边界清楚，助手生成带世界坐标 X/Z 顶点的 `manual_scope` 候选，按可见结构在门槛处闭合，并保存原始语义候选、证据、自动/人工修改来源及规则版本。边界证据不充分时标 `unresolved`，不要求负责人逐房补画；只将代表性问题汇总抽查。
5. 若只能得到蓝框而不能核验它代表的区域，不能将其作为主范围。只有蓝框世界坐标和楼层映射均可核验时，才记 `scope_source=website_bbox_aabb`、`scope_status=proxy_only`、`scope_analysis_class=bbox_proxy_only` 并单独报告；若只有截图像素框或无法核实坐标/楼层，则记 `scope_source=none`、`scope_status=unresolved`、`scope_analysis_class=unresolved`，不计算主指标、不自动舍弃。

网页 `bbox_image_fraction` 仅用于显示叠加，不得直接裁 navmesh。蓝框到世界坐标的转换正确，只能证明框的位置映射正确，不能证明框与房间身份/边界正确。最终结果须分别保存上述三个字段，不能用一个含义不明的“来源/状态”值代替。

可用 Habitat 加载原始场景并按 `region_id` 给成员面着色，渲染语义范围顶视图或叠加到 RGB 上；必要时为显示隐藏遮挡结构，但要保留语义成员面与场景 RGB 的核验图。渲染只能展示哪些面被标注为该 region，不能证明物理房间边界；面积需从带单位的世界坐标几何计算，不能按图像像素估算。

### 2.2 manual_scope / unresolved

manual_scope 依据 Habitat 场景 RGB、语义网格及可见墙体/门洞生成，不按面积阈值、颜色、bbox 中点或方便程度切割。保存多边形顶点、楼层、原始候选框、边界依据、生成方式、日期、版本及抽查状态。无法确定坐标、对象映射、楼层或物理范围则标 unresolved；停止该对象主面积计算，不自动舍弃，也不要求负责人逐项补边界。

若实际语义地面成员面明显进入邻室/走廊，先判断是 region 标注错误、开放式空间还是正常门口连接；单是蓝色 AABB 延伸到邻区不构成越界证据。边界可辨时用 manual_scope 修正；边界无法确认时记 scope_spillover/unresolved。只有研究目标明确包含连接区时才保留为复合范围，并单独标记，不称作单房间范围。不得为了通过面积门槛改边界。

楼梯/平台单列；楼层通过场景映射确定。楼层不清标 floor_level_ambiguous，不套未经核验的固定高度带。

## 3. 面积与几何计算

| 字段 | 操作定义 | 禁止解释 |
| --- | --- | --- |
| bbox_area_m2 | 世界坐标与楼层映射核验通过的网页蓝色候选 AABB，其 X/Z 长宽乘积 | 仅描述矩形外包框，不代表房间地面或可导航面积；映射未核实时记缺失 |
| semantic_floor_area_m2 | 原始清单/网页语义地面字段，连同原名、版本、定义一起保存 | 不是水平投影并集或 navmesh 面积 |
| bbox_proxy_nav_projected_area_m2 | 仅在 AABB 世界坐标和 floor_id 映射核验通过时，裁切 navmesh 并求水平投影并集 | 仅作框代理诊断，不进入主阈值和可用房间结论；映射未核实时记缺失 |
| semantic_floor_after_known_blockers_candidate_m2 | 经核验范围和 floor_id 内语义地面水平投影并集，减去已识别阻挡物投影并集 | 本方案主筛选面积，是几何候选指标；不证明 navmesh 可达或真实任务可用 |
| semantic_floor_conservative_candidate_m2 | 主地面候选再减去与之相交的未知/未映射物体几何投影并集 | 不确定性的保守面积下界；未知交叠仍单列，不等同于已确认障碍 |
| specified_scope_nav_projected_area_m2 | 目标 floor_id 内，navmesh 多边形裁切到已核验范围后，投影至水平面并求二维并集 | navmesh 范围支持诊断；不是主筛选面积，也不是人物实测活动面积或任务成功保证 |
| furniture_corrected_nav_area_m2 | navmesh 与语义地面相交并扣除已识别阻挡物投影并集后的面积 | navmesh 支持的地面候选面积，和主筛选面积分别报告 |
| semantic_ground_outside_navmesh_candidate_m2 | 已核验范围和楼层内，语义地面候选与 navmesh 不相交部分的水平投影并集 | navmesh 覆盖缺口候选；确认属于地面的部分计入主地面候选，但独立记录覆盖差异；不自动证明物理可达 |

当前审计 CSV 的物理列名为 `semantic_ground_outside_navmesh_area_m2`；读取和汇总时按本规则的标准名 `semantic_ground_outside_navmesh_candidate_m2` 解释。列名不同不表示已确认可行，也不表示已并入主面积。

固定操作顺序：

1. 检查 room_id↔region_id、范围几何来源/版本、世界坐标和 floor_id；批量规则能通过的范围可计算主指标，scope 仍为 candidate/unresolved 的对象不计算主指标。是否进入负责人抽查名单与是否逐房计算是两回事。
2. 在已核验范围和 floor_id 内独立提取语义地面面片，投影到水平面并求并集；不得只按蓝框 AABB、图片像素直接裁几何，也不得混合楼层。
3. 将桌、床、沙发、柜架、卫浴设施等已识别阻挡实例按记录的身体高度范围投影到对应楼层，先求物体占地并集，再从语义地面候选中扣除；重叠家具只扣一次，不额外扣未经核验的 agent 缓冲。
4. 主面积为地面候选减已识别阻挡物占地。将未知对象与未映射网格交叠单独记录，并从保守下界中扣除；只有当范围、楼层或关键几何无法判断时，主面积状态才标待核。
5. 独立计算 navmesh 范围面积、navmesh 支持的地面候选及 navmesh 外地面候选。确认属于同层地面的 navmesh 外区域进入主地面候选面积，不重复添加；navmesh 状态不能替代地面身份判定。
6. 未知类别或未映射网格与地面候选相交时，单列交叠并从 `semantic_floor_conservative_candidate_m2` 中暂时排除；该面积不能默认为障碍，也不能默认为可走。结构、扫描缺失或实例错配导致的重要交叠记 `unresolved`。
7. 楼层分别输出；楼梯作连接结构单列，坡面按水平投影计量并标记。无法判定楼层/坡面时记 floor_level_ambiguous。
8. 保存语义成员面/人工多边形来源及坐标、核验状态、floor_id、几何库/版本/精度和面积单位。

`semantic_floor_after_known_blockers_candidate_m2` 是主筛选面积；`semantic_floor_conservative_candidate_m2` 是未知/未映射交叠造成的保守下界。`specified_scope_nav_projected_area_m2` 和 `furniture_corrected_nav_area_m2` 作为 navmesh 支持诊断单列。原始面积、主候选、保守下界及 navmesh 支持面积均不得混名或相加成一个总量。

逐行状态优先于数值是否存在：范围或楼层未核的候选几何读数必须标为暂定，留在全量清单但不得进入主阈值总体或触发自动舍弃；几何不可计算时用空值并记录原因，不能把未知面积填成 0。

主范围外的相邻空间不计入主指标。若结构边界无法明确区分，保留 scope_spillover/unresolved 状态，不以蓝框外包矩形面积替代，也不悄悄改动源语义标注。

连通分量优先读取 Habitat 拓扑；重建邻接时记录算法和数值容差。无法稳定判定时不输出可信连通结论。连通数量、最大连通面积、框长短边、填充率和长宽比仅作描述；未经验证不得独立淘汰。

### 3.1 同一指定范围内的地面连接与语义分区

`region_id`、网格连通分量和“是否属于同一指定范围”是三个不同问题。两个地面片可能属于同一物理空间但被不同语义 `region_id` 或扫描网格切开；也可能由 navmesh 门洞相通、但物理上是两个相邻房间。不能仅按编号分开，也不能仅凭 `PathFinder` 有路就合并。

对用户指出“缺了一块/本应连通”的情况，固定执行以下核查：

1. 在同一楼层的 Habitat 原始 RGB 上并排叠加目标范围、全部相邻地面成员面、navmesh、墙/家具投影和扫描缺失区；同时检查世界坐标，不能只看缩放后的蓝框或颜色。
2. 分别记录地面几何是否接触、navmesh 是否连通、代表点之间是否可达，以及路径经过的语义区域和对象。`PathFinder` 成功只证明记录的 agent 配置在 navmesh 上可达，不单独决定房间边界。
3. 当区域分隔仅由 `region_id`/网格断缝造成，且同层地面边界连续、场景几何没有墙/门槛等空间分隔证据时，助手按该规则把完整相接地面并入同一指定范围；只并入实际相接/确认的局部，不扩成整个邻区。不得只加一条人为缓冲的窄路径带。
4. 若存在实体门墙、楼层差或场景边界无法自动识别，助手保留分开的组件并标 `scope_spillover` 或 `scope_geometry_unresolved`；不把“PathFinder 可达”单独写成“同一房间”，也不逐项请负责人裁决。仅抽查代表例，未解决项继续隔离在主统计外。
5. 若物理地面看起来连续、但 navmesh 或语义地面网格有断口，记录缺口为 `navmesh_floor_coverage_gap`、`semantic_region_incomplete` 或 `scan_missing_or_corrupt`；有独立因果证据才追加 `navmesh_static_obstacle_mismatch`。记录几何及面积，叠加图中分色。地面身份与 navmesh 支持是两个字段：确认属于目标范围的 navmesh 外地面进入主地面候选，另列 `semantic_ground_outside_navmesh_candidate_m2`；不得仅因未进入 navmesh 就称它在房间范围外。若目标范围归属也不清，另标 unresolved。

确认合并时保存被合并的组件 ID、各自几何、完整连接多边形、楼层、navmesh 路径/距离、范围依据、负责人确认和版本。面积用几何并集避免重复计数。连接组件不能只凭“离得近”“同层”或“有一条路径”自动合并。

## 4. 地板、颜色、形状与家具

- 不用 RGB 色值、黑色比例或纹理分割直接画框或淘汰。
- 木地板、黑白瓷砖、彩色/花纹地面、地毯和材质变化均不自动判坏。
- `shower floor`、`bathroom floor`、`bath floor` 作为浴室地面候选；`bath mat`、`bathroom mat`、`shower mat`、`bathroom rug` 等作为地面覆盖候选。标签只帮助提取相应三维表面，不能单凭标签就认定整个区域可达：仍须核对面片高度、所在楼层、目标范围归属与原始 RGB，并分别求 navmesh 支持部分和未覆盖部分。未被 navmesh 支持但已确认属于同层地面的浴室区域进入主地面候选面积，同时记覆盖缺口；不能误标成家具或重复加面积。
- L 型、凹形、弧形和非矩形范围可保留；不得因矩形框填充率低就自动判走廊。
- 地毯/地垫属于地面候选，不是默认障碍或独立房间；在经核验的目标范围内，若场景几何显示其为平整、连续的表面，应保留为地面候选，不因颜色深、材质不同或语义 region 编号不同而漏掉。必须分别记录地面身份与 navmesh 覆盖：navmesh 覆盖部分计入 navmesh 支持面积；navmesh 未覆盖但确认属于地面的部分标为 `navmesh_floor_coverage_gap`，进入主地面候选并单列几何和面积。
- 物体判断以**实例和投影几何**为单位，不能把某类标签一概当作障碍或通行面。`table/desk`、沙发、柜、卫浴设施等类别只用于定位待核对象；逐实例记录 `exclude_confirmed`（确认为阻挡）、`keep_floor`（负责人确认该片是地面/应保留）、`review`（对象或投影不清）三种处理状态及证据。
- 对确认为阻挡的物体，使用语义实例/场景网格的三维几何投影到对应楼层；尽量用三角面投影并集保持真实轮廓，不以整实例轴对齐框或凸包直接扣地面。将直接占地与 agent 半径缓冲分开记录；代理参数未知时不得把缓冲说成已验证的真实碰撞边界。
- `sunbed`、`lounger`、`recliner`、`chaise`、`daybed` 等躺椅/卧榻标签与椅子、床同属家具阻挡物候选。标签仅用于定位实例；须核实实例、可见物体和坐标投影对应，确认后按其实际水平占地及记录的 agent 代理缓冲扣除。不能因颜色浅、网格稀疏或语义实例只覆盖部分表面就把躺椅留在可行域；实例几何缺失/错配时标 `review` 并修正或补画单实例轮廓，不能猜测扩扣周边地面。
- 桌面、台面等水平表面也属于物体占地，不能因为只识别到桌腿、实例标签缺失或 navmesh 穿过而把台面保留成绿色。若三维实例轮廓没有覆盖 RGB 中可见的桌面/家具，先检查实例映射、垂直范围、坐标变换和投影是否漏面；负责人确认后，以单实例的人工几何补足阻挡面并保留原自动几何作对照。
- 家具投影按物体几何确定，不沿 RGB 阴影扩张。沙发/桌子投下的暗影不能单独算作家具占地；若自动掩膜覆盖了影子却没有覆盖物体本身，应回到三维实例与可见表面轮廓核对。
- 跨语义区的家具只按其三维投影与**已核验目标范围**的实际交集处理。不能仅因家具属于邻区就忽略其对目标范围的遮挡，也不能仅因语义类别/名称相同就扣除远处或范围外对象。若目标范围映射不符，先核范围，不挪用邻区对象修补面积。
- 对“红色/橙色多扣了地面”的反馈，不把整块差异一概恢复。检查它来自真实物体投影、agent 缓冲、凸包残差、未知网格还是颜色叠加；只有负责人指明并确认的地面几何才以 `keep_floor` 加回。凸包与保形投影的差异默认单列为不确定几何，不自动判地面。
- 细小三角、窄片或边角不能仅因形状不规则/面积小就独立判成障碍。若它与周围地板材质、几何表面连续，且没有物体实例或结构边界支持排除，应沿同一地面候选处理；证据不足时标 `review`，不能只凭其形状画成异类。
- 未映射语义面/黑色或白色表面不自动算作地面或阻挡物。负责人可以在原始 RGB 与几何叠加上确认具体多边形为地面；确认结果必须落到坐标和楼层，不能只记录“黑色都算地面”或“白色都排除”。未确认部分继续 `review`，不默默加入/扣除。
- 范围核验预览必须先复现审阅平台当前对象框：使用该条目的 `bbox_image_fraction`，在同一张 1024×1024 RGB 画布上画平台同款青色轴对齐矩形（`#00ffff`、3 px、无填充），位置和大小不得重新估算。左侧保留原始 Habitat RGB，右侧显示同一 RGB 加对象框。该框表示网页使用的语义几何 AABB 候选，不是精确墙线，也不自动证明真实房间范围正确。标题应说明该俯视图的物理画幅，以及框占图的比例；框外是渲染上下文，不属于该蓝框候选。若蓝框覆盖整幅画面，要直接注明“范围框覆盖全图”；不要再画一个语义网格轮廓来代替对象框。若还需显示语义地面面片、家具或 navmesh，使用半透明填充或与青色框明显不同的图例；网格内部边、孔洞和碎片轮廓不得伪装成对象范围线。若从相邻区域借入局部连接地面，另用独立颜色标出该局部补片，不改写平台对象框。图例分别定义“平台对象框候选、地面候选、确认阻挡、未知/待核、navmesh 未覆盖地面、局部连接补片”。同一种填充颜色只表达一种状态；不要用仅靠透明叠色或未说明的红/绿让人猜测是否计入。渲染不改变底图像素或输入几何。

### 4.1 由人工反馈修正掩膜的标准流程

自然语言意见先归为**误扣地面、漏扣物体、漏覆盖/连接、未知表面、用途判断、无明显问题**之一；一条意见可有多个标签。随后把文字指向具体实例、地面多边形或组件；无法唯一映射时不猜，记待核并展示证据。

每次修正只执行意见明确要求的几何操作：

1. `误扣地面`：定位被错误扣除的掩膜来源及精确区域，检查凸包超界/轮廓变形；用负责人确认的地面多边形恢复，不恢复整个家具实例周边或所有红色区域。
2. `漏扣物体`：定位可见对象对应的实例和桌面/占地投影，补足确实漏掉的遮挡几何；确认对象后的候选掩膜与该对象投影不再相交。其他已核验的扣除保持不变。
3. `漏覆盖/连接`：按第 3.1 节检查同层范围、navmesh 可达和物理边界；不能因 `region_id` 不同就拆开，也不能因 PathFinder 可达就自动合并。负责人确认属于同一目标范围后，对确认参与连接的完整地面组件执行并集，不以窄路径缓冲代替连接区域，也不自动并入整间邻室。
4. `未知表面`：保留独立 review 掩膜；负责人若确认某一具体面可行/不可行，则只修改对应几何，并记录其来源和负责人确认。
5. `用途判断/小或无意义`：保留几何和面积；单独记录人工用途意见，不反向改边界或从单例推导全局面积阈值。负责人明确人工舍弃的单例可记人工决定，但不充当统计阈值证据。
6. `无明显问题`：保留作对照；这只表示负责人没有从图像指出几何修改，不会自动消除网格、楼层或数据质量异常码。

漏扣家具必须做两层核验：先核对三维语义实例/场景网格的投影是否覆盖可见物体，再在 Habitat 原始 RGB 上逐个检查桌面、台面等水平表面是否落在排除掩膜内。实例投影与候选区交集为零只是几何检查，若实例本身漏面、错配或坐标偏移，不能据此宣布家具已排除；须由负责人对可见物体轮廓补画/校准单实例占地，或记 `review`。最终确认的物体占地/代理缓冲与候选地面的交集，应不超过该结果所记录的 navmesh 单元面积容差；超出则返修。

修正前后都保存逐实例掩膜与面积、修改几何、原因、图像版本和反馈记录。审阅前后差异要以二值掩膜/几何面积核验，不能仅凭半透明叠加图判定修正成功。审核记录保留历史；后续澄清以带时间的更正记录覆盖旧的**解释**。原始意见和样本级记录存于仓库外，不随代码发布。

### 4.2 房间范围、地面完整性与显示

1. **范围来源分开记录。** 网页 AABB/蓝色框仅是语义区域成员面的轴对齐外接框候选，不等同物理房间轮廓。主面积只使用通过核验的 `semantic_region_verified` 或 `manual_scope`；仅有 AABB 时单列 `bbox_proxy_only`，不混入主面积或阈值。
2. **逐组件核对覆盖。** 在目标范围和楼层内枚举地面组件，分别标记已纳入、已确认阻挡、navmesh 未覆盖或待核。只处理画面中最大区域、漏掉卫生间/门口等明显地面时，记 `analysis_coverage_incomplete`，暂停筛选结论。
3. **材质与颜色不是地面真值。** 木地板、瓷砖、地毯及颜色花纹差异不构成排除理由。结合语义面片、原始扫描几何、RGB 和楼层判断；颜色或纹理单独不能判地面、家具或阴影。
4. **地面身份与 navmesh 覆盖分开。** 已核实的目标范围地面即使未进入 navmesh，仍进入主地面候选；navmesh 外地面另记 `navmesh_floor_coverage_gap`，不计为 navmesh 支持面积，也不得误称房间外区域。
5. **空候选必须解释。** 展示“候选为空”及可核验原因，例如无地面网格、范围/楼层未对齐、navmesh 无交集、障碍物扣除或输入缺失。图层/渲染失败时先记 `review_visualization_failure`，不把空画面当作零面积。

### 4.3 家具、桌面与实例占地

1. **按实例计算物体本体占地。** 对桌椅、沙发、床、柜体、台面、家电和卫浴设施等识别到的实例，核对三维语义实例、楼层、高度带和投影。桌面、书架顶面、床架等物体表面不可算作地面；扫描网格只保留桌沿等部分面片时，需用实例投影补足桌面内部，避免把桌面误留为候选。
2. **局部反馈只改对应局部。** 若抽查指出只漏扣一件家具，保留其他已核验扣除，只修该实例；不得恢复所有已扣区域或扩大扣除到周围地面。
3. **阴影不属于物体占地。** 红/暗色影子、反光、贴图和材质变化不能单独生成阻挡掩膜。只按物体几何足迹及单独记录的代理缓冲扣除。
4. **形状保真并集后再扣除。** 同一物体多片面片先按实例合并，多个物体占地求并集后只扣一次。L 形家具或非凸轮廓不得因便利而用明显过大的凸包吞掉周围地面；不确定实例标 `review` 并保留交叠证据。
5. **未知对象不静默归类。** 语义未映射、几何缺面或实例错配时记录为 `unknown/review` 及其面积；不得默认为可行地面或家具。

### 4.4 邻接区域、门口连接与连通

1. **region 标签不是物理隔断。** 相邻 `region_id` 的同层地面若在几何上连续，不因标签不同自动割裂；若存在墙、门槛、家具或真实间隔，也不能只因距离近就合并。
2. **补入范围必须有边界证据。** 仅把证据确认属于目标范围的局部连接地面纳入；不能因 AABB 覆盖或空间接近就并入整间邻房。若真实范围边界不明，记 `scope_geometry_unresolved`。
3. **不绘制虚假通道。** 两片候选之间若存在真实空隙或结构阻挡，保留为分离连通分量；若确认只是语义分区/扫描网格缝，纳入实际完整地面几何，不只添加一条人为窄线。保存修改前后组件数和几何差异。
4. **几何连通不等于声音连通。** 输出平面/三维组件及 navmesh 连通信息；不得用面积、平面距离或 navmesh 路径推断声学互通或听觉任务适用性。

### 4.5 抽查意见如何推广

1. 将自由文本拆成可定位对象/组件、楼层、期望动作（纳入地面、排除物体、核边界、修图等）和证据状态；不能唯一定位时不猜多边形。
2. 单例意见仅直接修对应对象。推广到同类对象前，先写成机器可检查的条件（例如同类别实例标签、同层交叠、相同遮挡/覆盖缺口），由助手批量筛出同类对象并处理；条件不满足或证据冲突者保留 `review/unresolved`。
3. 标签按钮只作快速归类；文字说明优先表达具体修正意图。修改前后保存几何版本、面积、分量数、理由码和图例/规则版本。个人原始反馈、具体样本清单和审阅媒体保存在仓库外，不随代码发布。
4. 负责人抽查少量代表/高风险样本；自动流程负责同类对象的全量应用。抽样不能被表述为所有对象均经人工确认。

### 4.6 面积计算与后续可用筛选分离

1. 面积阶段先修正范围、地面完整性、家具占地和楼层；“房间不用、太小、狭窄、走廊/楼梯主导、家具缺失”等用途建议不得清空或篡改面积掩膜。
2. 面积和形状计算完成后，再分别记录空间类型、家具观察状态、可行域总面积、连通分量及其占比、局部宽度/细长度、技术异常和处理建议。
3. 面积下限和形状门槛须通过完整分布、敏感性分析和项目负责人审阅后另行冻结。单个样本、旧的面积值或 AABB 长宽比不能单独决定全局阈值。
4. 范围过宽时只有找到真实墙体、门洞或功能边界，才建立 `manual_scope` 裁剪；裁后重算并保留来源、修改前后面积及理由。AABB 大、颜色不同或空间相邻本身不触发裁剪。


## 5. Agent 与 navmesh 参数

每组正式结果记录 Habitat/场景版本、agent 半径和高度、cell size、cell height、最大坡度、最大跨越高度、静态物体设置、navmesh 来源及生成/加载状态。旧参数无法核验标为未知，不和统一配置结果混称。

“人物碰撞半径可能取源半径一半”仅是待核验说法。记录实际导入碰撞体；不能确认时用的配置标 temporary_agent_proxy。结论限于记录的 agent navmesh 几何代理，不宣称真实人物无碰撞通行。

## 6. 助手全量初判与项目负责人抽查

固定问题为：“在经核验的指定房间范围和对应楼层内，是否存在明确的房间主体可行域？”

- **present：** 有连续的主体内部可行域；不是只有门口带、贴墙窄条或零散网格片。
- **absent：** 范围和数据可判读，但主要是通道、楼梯、狭长边缘或伪片，没有明确主体区域。
- **uncertain：** 范围有效，但扫描、navmesh、范围外溢或主体判读仍有疑点。
- **unassessable：** 对象映射、世界坐标、楼层、场景或 navmesh 失败，无法有效判断。

助手对全量输出建议标签、证据和异常；项目负责人只抽查少量代表/高风险样本并修正规则，不逐项检查。仅被实际抽查的对象记录负责人终判；其余保留助手标签和机器置信/异常标记，不能冒称人工真值。用于 95% 统计阈值的人工标注样本属于单独的后续验证工作；在样本量不足时关闭自动面积筛除，不把补齐样本的负担转成全量逐房审核。该流程不是两个独立人类审核者；不报告 Cohen’s kappa 或双人一致率。

审核图统一显示原始 RGB、语义 region 成员面/候选蓝框、目标范围实线、navmesh、楼层和物理比例尺；必要时显示 manual_scope 边界，隐藏数值面积、候选阈值、自动处理建议和旧 verdict；负责人会看到助手初判，因此材料不称双盲。校准例需涵盖门口连接、楼梯/多层、扫描缺损、不规则边界、多材质地面和网格碎片。负责人只审冻结的少量抽查名单；未人工确认的标签不得用于正式 95% 阈值验证，样本不足则对应筛除策略保持关闭。不得为启用阈值而要求负责人复核全量。

标签用于项目操作性几何筛选，不是真实物理或下游任务真值。present 和 uncertain 作为保守正例；absent 不进入正例分母；unassessable 不进入统计且永不自动舍弃。

## 7. 抽样、面积阈值与整体保留率

### 7.1 场景抽样

抽样单位是场景，不是单独房间；层内按冻结种子无放回抽取。正式抽样框排除独立试运行场景。助手对抽中场景的全部可评估房间初判；负责人只按冻结的人工抽查量检查其中选定对象，不逐个审完整个抽中场景。人工样本不足时不启用面积自动筛除。

标签揭示前冻结场景层：
- 主抽样框只包含 semantic_region_verified 与 manual_scope 主范围。场景全部主范围均来自核验语义区域时记 semantic_region_only；含任一 manual_scope 时记 contains_manual_scope。bbox_proxy_only 与 unresolved 不进入面积阈值总体，另行统计。
- 按场景内指定房间范围可导航面积中位数切为四分位面积层，保存切点、NumPy 版本与分位算法。
- 两字段交叉成层；少于 4 个场景的面积层按 Plan 规则在同一来源类内合并。合并后来源类总场景仍少于 4 时全查、权重为 1、area_filter_off，不参与自动阈值筛除。

在每个可推断层按 Plan 6.2 冻结的抽样比例组合，先抽 development，再从余下场景抽不重叠的 validation。候选组合是 f_D、f_V 各取 0.25、0.50、0.75、1.00 的 16 种组合；nD_h 与 nV_h 按 Plan 6.2 的整数公式计算。按预期复核房间数从低到高，依序执行冻结模拟验收，首个通过方案为正式分配；失败后试下一个，不临时改变网格或门槛。无方案通过时，全查后重新评估；仍未通过或无法完成验收，相关来源域不开启面积自动舍弃。

冻结各层 N_h、nD_h、nV_h、场景名单、代码和随机种子。Development 阈值选择权重为 N_h/nD_h；validation 对 development 外总体的条件权重为 (N_h−nD_h)/nV_h；全查时权重为 1。已普查的稀疏来源类作为已知固定贡献。抽中场景内各房间继承场景权重。逐房不可评估项仍登记，不进入主面积统计，且永不自动舍弃。

### 7.2 Development 只用于选阈值

用于阈值选择的正例须来自负责人实际抽查并确认的 present 与 uncertain；助手全量标签不能冒充人工真值。各房间范围来源域分别枚举候选 T_g，覆盖该域 development 面积产生的全部不同切分，并包括“不筛除”；只有面积严格小于对应 T_g 才列入舍弃候选。area_filter_off 来源域一律保留；人工样本量不够时保持关闭。

按房间范围来源分别确定阈值，不将一个全局 T 默认套给语义成员面范围和人工范围。对 semantic_region_verified 与 manual_scope 各自枚举该域 development 面积的不同取值；因仅 area<T_g 才进入候选，取最小观测值代表不筛除，并另设“不筛除”选项。用 development 抽样权重选满足域内正例保留率至少 95% 的最大 T_g。正例不足两个场景、缺少 validation 支持或域不可评估时，预先将该域设为 area_filter_off。整体策略是各来源域冻结的 T_g/关闭规则的组合；不另行拟合第三个整体阈值。Development 保留率是阈值选择条件，不是独立验证结果；95% 是本项目工程目标，不是通用行业标准。

### 7.3 估计整个正式抽样框

令 C 为少于 4 个场景而全查、预先设为 area_filter_off 的已知固定场景；D 为其余抽样框中 development 已终审对象；R 为 D 以外的可推断场景总体；V 为从 R 抽中的 validation 对象。y=1 表示终审标签为 present/uncertain；keep=1 表示按房间来源对应的冻结 T_g 保留，或来源类为 area_filter_off。

- C 与 D 按已知实际计数加入：正例分别为 Σ_C y、Σ_D y；保留正例分别为 Σ_C y·keep、Σ_D y·keep。C 中 keep=1。
- V 用条件权重估计 R 的正例数及保留正例数，权重为 (N_h−nD_h)/nV_h；若某层剩余场景全查，则权重为 1，作为已知固定贡献。
- 全范围保留率估计 =（C 与 D 的实际保留正例数 + V 加权估计的 R 保留正例数）÷（C 与 D 的实际正例数 + V 加权估计的 R 正例数）。

Development 选阈值时用扩展权重；计算整个有限抽样框时，C 和 D 已知对象按实际计数加入，不乘扩展权重。Validation-only 留出表现另行报告，不能替代全范围合并结果。

若正式抽样框对声明涉及的所有场景均已全查，则保留率为精确值，不计算抽样区间。否则以 validation 场景作为 PSU、每层剩余总体数 N_h−nD_h 作为有限总体数，使用 R survey 包的 mrbbootstrap 类型生成 10,000 组 replicate weights。C、D 和 validation 全查层均为已知固定贡献，重复权重不得改变；只对有抽样误差的 validation 层生成 replicate weights。构建设计时记录 R 与 survey 版本、FPC 类型、scale、rscales、MSE 设置和随机种子。每组 replicate weights 都要重新计算 validation 对 R 的正例总数和保留正例总数，再加回 C、D 的固定计数，得到全范围比率；对其 logit 使用 replicate design 方差设置计算标准误和 t 区间，再反变换为保留率区间。自由度取 validation 随机抽取 PSU 数减去非全查层数。不得只对 validation 子样本算比例而忽略 C、D，也不得把 replicate 比率原始分位数称为 survey 置信区间或逐房 bootstrap。正例分母为 0、自由度不为正、非全查比例为 0/1、分母不稳定或 replicate 无法计算时，区间无效，相关域关闭自动过滤。

### 7.4 模拟验收

正式启用面积自动筛除前，必须按 Plan 6.5 对完整统计流程做标签已知的合成有限总体模拟。模拟保留 181 栋清单中真实的场景房间数、面积分布和来源构成；按场景生成相关标签，不把房间误当独立样本。模拟范围、面积字段和范围来源与 Plan 一致。

按 Plan 6.5 的固定模型生成标签：logit(P(y_i=1))=α+γM_i+β₁x_i+β₂q_i+δ(M_i×x_i)+u_scene，其中 M_i 标记 manual_scope，x_i 是标准化 log(area)，q_i 是中心化平方项再标准化，u_scene 是正态场景随机截距。机制覆盖无面积关联、优势比为 1.25/1.5/2 及其倒数的单调关系、U 形/倒 U 形、来源基线差异和来源×面积交互；正例比例覆盖 20%、50%、80%；场景随机效应覆盖 0、试运行估计和其场景 bootstrap 95% 上界。系数网格是本项目压力测试参数，不是数据集事实或领域标准。模型参数、软件版本、收敛结果及配置写入模拟清单。参数不稳定或不能支持某来源域时，不得只用有利情景替代，应关闭该域自动过滤。

先用独立调试种子确定并冻结边界情景，使每种关键机制至少覆盖真实正例保留率低于 95%、94.5%–95.5% 和高于 95%；用完整合成标签计算真实保留率只用于事后模拟评分，阈值选择不得读取 validation 或未抽中场景的标签。调试运行不计入验收。正式验收使用新的冻结种子和代码哈希；每个主要情景至少 1,000 次完整流程，每次概率 validation 使用 1,000 组 replicate weights。

逐情景报告 overall、semantic_region_verified、manual_scope 的家族同时区间覆盖率、真实保留率低于 95% 时错误启用率及其单侧 95% 精确二项区间、区间半宽、无效区间/零分母比例、各比例分子分母及 Monte Carlo 区间。覆盖率须为 93%–97%；低于 95% 的关键情景中，错误启用率上界须不超过 7%。未达到重复数、边界情景缺失、代码或参数无法复现、无效区间或任一关键情景失败，均不得开启受影响来源域的自动面积舍弃。模拟只评估统计实现对预设合成机制的表现，不证明标签真值或下游任务可用性。

## 8. 四类处理建议、旧值和裁剪

旧流程 6 m²、50 m²、短边 2.2 m 只作历史对照；先核实其字段和单位，不得直接套在指定房间范围内可导航面积上。50 m²只触发大范围复核/裁剪候选检查，不自动裁剪。

- **保留：** 房间范围和楼层可评估，终审标签为 present；项目类别另记。
- **舍弃候选：** 明确非目标类别、终审 absent，或通过验证的面积流程提出候选。自动建议不等于删除；执行前负责人确认。
- **裁剪：** 有真实墙体、门洞或功能边界依据；生成新 manual_scope 并重新计算。
- **存疑：** 坐标/楼层/扫描/navmesh/范围溢出关系不清、终审 uncertain 或结果敏感。

不按面积、地板颜色、bbox 中点或方便程度切分。无真实分界的开放空间保留为复合范围或存疑。小连通区域不能仅因面积小删除。

### 8.1 面积核算后的后续场景筛选（当前阶段暂不执行）

此阶段只在指定范围、楼层、家具占地和可行域面积通过第 2–4 节核验后启动。若地面组件漏项、家具占地未核清、navmesh 覆盖缺口/楼层错位未解释，或存在 `analysis_coverage_incomplete`、`review_visualization_failure`，先返修或记存疑；不得将计算缺陷误判为“不适用”。**筛选顺序固定为：数据质量门 → 场景类型/家具盘点 → 可行域面积 → 连通性与形状 → 大范围裁剪候选。** 所有阶段都先输出候选建议，正式删除由负责人确认；小面积和形状阈值未冻结前不得自动淘汰。

#### 第一道：数据质量门

场景、视图、范围和楼层可核验后才进入场景筛选。渲染全黑或范围/楼层错配时先重渲染、校准或修复；仍无法核实时记 `unassessable`，不把面积记为 0，也不把几何质量问题冒充“房间不适用”。确实无法修复的对象可以因证据不可用而进入单独的技术性舍弃候选。

#### 第二道：场景类型与家具盘点

| 检查项 | 记录方式 | 候选处理 |
| --- | --- | --- |
| 家具/场景物件 | `furnishing_status` 记 `present`、`none_observed` 或 `unknown`；能识别时另记类别与实例 | 家具存在与否先作场景内容标签。只有任务已明确要求的家具/交互类别缺失时，才产生 `task_furnishing_missing` 舍弃候选；未定义必需类别时不因“没家具”单独淘汰。 |
| 主要是纯长廊 | `space_type_tags` 记 `corridor_dominated`，并核对是否确实没有房间主体 | 提出 `corridor_stair_dominated` 舍弃候选。不能只凭 AABB 长宽比、某一条狭长通道或相机视野判定；与房间主体相连的普通过道不单独使对象失效。 |
| 主要是楼梯/楼梯井 | 记 `stair_dominated`；楼梯踏步和跨层连接面与楼层平面分开 | 没有明确房间主体时提出舍弃候选；若楼梯只是房间/平台的一部分，单列楼梯连接结构，不把整条楼梯当作平层可行面积。 |
| 房间主体与走廊/楼梯并存 | 记 `room_body_present`、`mixed_room_corridor` 等标签 | 保留主体空间评估；只按已核实的物理边界区分组件，不因局部含走廊或楼梯整间淘汰。 |

状态解释：机器确认至少一个阻挡物实例与目标地面几何相交时可记 `present`；没有识别到阻挡物不等于没有家具，仍记 `unknown`。只有完整 RGB/语义覆盖经人工查看后确实没有家具，才记 `none_observed`。空间类型缺乏结构证据时记 `unknown`，不能从长宽比或大 AABB 自动标作走廊。

“家具存在”本身不等于适用，“没有家具”也不自动等于不适用；本步骤要求先查明并记录，以便按已经冻结的任务内容要求筛选。当前没有必需家具类别清单，因此缺家具只能记条件候选，不能直接批量删除。

#### 第三道：可行域面积下限

只使用完成范围/楼层核验并按 Plan 冻结定义计算的主面积 `semantic_floor_after_known_blockers_candidate_m2`。未知/未映射交叠影响另列面积不确定性与保守下界；面积状态未决的对象不自动跨阈值分类。navmesh 面积作独立覆盖诊断，不替代主筛选面积。设任务最小面积为 `A_task_min`，当主面积 **严格小于** 已冻结的 `A_task_min` 时标记 `small_residual_area` 并提出舍弃候选；等于下限不因本条规则淘汰。面积下限必须先基于完整、校准后的目标场景面积分布，结合保留数量和场景类型敏感性分析确定；少量人工样例只能帮助定位，不得单独决定下限。`A_task_min` 尚未冻结时，只报告分布和候选，不执行面积淘汰。

#### 第四道：连通性与形状

在同一指定范围、同一楼层和家具修正后的可行域几何上计算组件数量、各组件面积、最大组件面积占比、组件间距离、局部宽度分布及范围内长短轴比。不得用跨房间 AABB 直接代替可行域形状。

| 形状情形 | 操作规则 |
| --- | --- |
| 大量彼此分开的零碎小块，没有占主导的连续主体 | 标 `fragmented_feasible_area`，提出舍弃候选；先确认不是语义标签断缝、扫描缺失或 navmesh 漏覆盖。多个组件的固定数量或占比阈值尚未冻结，须结合全量分布和代表性图像校准。 |
| 又细又长的条带，主要体现为狭窄连接而非可用主体 | 同时参考局部宽度和范围内长短轴比；确认属于纯走廊时按第二道处理，否则标 `elongated_narrow_area` 并提出舍弃候选。宽而长的真实房间不能只因长宽比高就淘汰。数值阈值尚未冻结，不执行自动淘汰。 |
| 主体可行域连续、面积与局部宽度充分，只有少量附属碎片 | 保留主体并记录碎片；不可仅因存在多个几何组件就把整个对象判作不可用。 |

#### 第五道：面积过大与裁剪候选

面积明显偏大或范围疑似合并多个房间时标 `large_area_review` / `crop_candidate`，进入后续切分检查，不直接舍弃。先核对真实墙体、门洞、楼梯口或功能边界；有依据时沿这些物理边界建立子范围，分别重新计算面积、连接和形状。旧 `50 m²` 只保留为大范围复核提示，不是自动裁剪线。开放空间没有可核实边界时不得为满足面积值任意切块，保留复合范围或标存疑，等待任务层决策。

| 筛选原因 | 操作规则 | 当前状态 |
| --- | --- | --- |
| `corridor_stair_dominated` | 房间主体缺失且主要为长廊/楼梯时提出舍弃候选，保留面积与范围记录。 | 按第二道执行；需有空间结构证据。 |
| `task_furnishing_missing` | 仅在任务必需类别清单冻结后，将缺失类别提出舍弃候选。 | 类别清单尚未冻结，不自动淘汰。 |
| `small_residual_area` | 面积严格低于冻结的 `A_task_min` 时提出舍弃候选；下限冻结前只做分布和敏感性分析。 | 历史小面积样本只用于定位复核类型，不作为阈值。 |
| `fragmented_feasible_area` | 经确认是实际断开的多个小碎片、且无明确主体时提出舍弃候选；先排除数据缺口。 | 分量阈值待全量分布和后续校准后冻结。 |
| `elongated_narrow_area` | 局部宽度低且形状狭长，缺少有效主体时提出舍弃候选；不以长宽比单独判定。 | 宽度/长宽比阈值待校准。 |
| `large_area_review` / `crop_candidate` | 过大或疑似跨多房间时核查真实边界；有边界再切分、分别重算。 | `50 m²` 只作复核提示，不自动裁剪。 |
| `area_or_scope_unresolved` | 继续标存疑/返修，不纳入最终可用/不用判断。 | 面积覆盖明显不完整时，先修正范围、楼层和几何计算。 |

`A_task_min` 与第 7 节 95% 正例保留率约束的统计阈值是两种不同决策：前者回答单个场景是否满足已定义的任务空间需求，后者控制面积筛除对盲审正例的总体保留表现。两者分别报告，不得用一个阈值替代另一个；两者都不能从少数反馈样本直接估出。所有处理建议在负责人最终决定前都只是候选，不能自动删除或改写原始审核 verdict。

每个对象记录 `post_area_screening_status`、`post_area_reason_codes`、判定依据、范围/面积版本及负责人最终决定；同时记录 `furnishing_status`（present/none_observed/unknown）、`space_type_tags`、观察到的家具类别、组件面积分布、最大组件占比、局部宽度、范围内长短轴比，以及所用面积/形状阈值和规则版本。阈值尚未冻结时显式记 `pending`，不得填入推测值。家具内容筛选启用时另记 `task_context_inventory`：任务要求的类别、观察到的实例、presence/absence/unknown 和证据路径；要求清单未冻结时仅作描述，不触发淘汰。

对审阅掩膜另做针对性验收：被确认阻挡的桌面/家具不得残留在候选掩膜；被确认保留的地面不得继续被家具凸包、不明颜色或影子排除；细碎地面片不得只因形状独特而被单独扣除；同一指定范围内确认连通的组件不得仅因语义 region 标签而割裂；相邻区域只借入负责人确认的局部连接块，不把整个邻区一并合入；卫生间及多材质地面组件须纳入完整性检查；语义地面存在但 navmesh 未覆盖的部分单列为覆盖缺口；空候选必须显示空状态和原因；审阅图必须有标明来源状态的目标范围实线；unknown 面不得静默归类；用户标为“无明显问题”的控制样本只核图像意见，不抹掉技术异常码。每项按二值几何交集/并集、组件连通结果与成对审阅图共同验收。

## 10. 允许的结论

可表述为：在 181 栋指定场景中，助手批量核验 HM3D `region_id` 与审核对象的对应关系及成员面几何；网页蓝框只作语义区域 AABB 候选。按同一目标楼层提取语义地面，求水平投影并集并扣除已识别阻挡物占地，作为地面候选面积；未知/未映射交叠另列上下界。Habitat navmesh 支持面积和 navmesh 外的地面候选分开报告，不能互相替代。负责人抽查少量代表/高风险对象，反馈用于更新规则并批量重算；未抽查对象保留自动来源和异常状态。面积阈值是后续独立验证步骤，人工样本不足时不启用自动面积筛除。只有蓝框、但范围无法核验的对象单独报告，不进入主阈值分析。

不得称该面积为精确墙内净面积、真实人物无碰撞通行保证、摄像机/声学/任务适用性证明，或全部 HM3D 场景通用结论。
