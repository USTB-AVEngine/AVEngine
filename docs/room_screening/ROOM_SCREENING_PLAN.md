# HM3D 房间筛选与指定房间范围可导航面积评估主方案

> **文档状态：** 当前方法主方案。数据字段、坐标映射和运行参数在实际核验前均标为待核验；试运行后冻结并留档。
> **范围：** 团队已下载的 181 栋 HM3D 场景。
> **规则文件关系：** ROOM_SCREENING_RULES.md 是本方案的执行细则；两者不一致时以本方案为准。
> **当前执行口径（V12，2026-10-06）：**主面积为同层语义地面扣已识别阻挡物并集，并纳入经反馈及同层几何/空间证据确认的地面补片。1.80 m/0.20 m 探针只作碰撞、漏区和连接核查，不把探针格面积加减到主面积。AABB 是范围参考，不是物理墙线。10 m²为项目初筛下限。全量结果见 [运行摘要](EXECUTION_SUMMARY_20261007.md)。

## 1. 目标、范围与结论边界

从 181 栋场景的完整候选房间清单出发，由助手批量核验或建立可追溯的空间范围几何，计算地面候选与 navmesh 支持指标，并给出“保留、舍弃候选、裁剪、存疑”建议。负责人只抽查少量代表/高风险样本；主筛选面积是**经核验范围和楼层内的语义地面水平投影并集，扣除已识别阻挡物占地后的候选面积**。navmesh 支持面积另列，不与地面候选面积混称。

审阅网页中各类框线和“主指标边界”的定义见第 2.2 节。关键区别是：网页蓝框只是语义区域的 AABB 候选；主面积使用按冻结规则通过核验的指定房间范围几何，并保留自动/抽查来源状态。主面积表示地面候选，不证明该地面全部被 navmesh 覆盖或真实人物可达。

本阶段只做几何筛选，不评估人物路线、动画、物品摆放、摄像机位置或视野、声学质量或下游任务表现。结论只适用于这 181 栋、经核验的指定房间范围、楼层和 Habitat navmesh agent 配置，不外推到全部 HM3D 或未定义的实际任务。

## 2. 数据清单、房间范围几何来源与核验

### 2.1 冻结输入清单

正式计算前逐栋建立输入清单，至少记录场景 ID、GLB 路径与校验值、Habitat 版本、房间清单与语义文件路径/版本、room_id↔region_id 映射、成员面几何可用性、蓝框字段、`scope_source`、`scope_status`、派生分析类别 `scope_analysis_class`、楼层信息、navmesh 来源/参数状态、文件可读性及缺失原因。所有原始房间条目先入清单，再处理；不得按面积预筛而静默漏项。

HM3D-Semantics 发布说明列出 216 个场景、约 3,100 个房间标注，不代表目标 181 栋都具有完整标注。[官方说明](https://aihabitat.org/datasets/hm3d-semantics/)。逐栋盘点并分开报告已核验的语义区域几何、人工修订范围、仅有蓝框代理和无法评估对象。

### 2.2 指定房间范围：定义、解释与核验状态

先区分“图上看到的框”和“计算时采用的房间范围”。**主指标的边界是经冻结规则核验并保存为可追溯几何的指定房间范围；负责人抽查少量样本校验规则，不逐对象确认；不能仅凭某种颜色的线框认定。**

| 名称 | 定义 | 解释与处理 |
| --- | --- | --- |
| 主指标使用的指定房间范围 | 用于限制目标楼层语义地面与阻挡物几何的世界坐标范围。 | 来源为按冻结规则核验通过的语义区域几何或有场景依据的人工范围；须完成映射、楼层和地面覆盖等机器核验，并保留 `assistant_auto`/owner_spotcheck 来源。它是计算边界，不等同于未经核验的网页线框。 |
| `semantic_region_candidate`（语义区域候选） | HM3D 语义标注中目标 `region_id` 的成员面构成的几何。 | 先核验 `room_id↔region_id` 映射、楼层和地面覆盖，再与 Habitat RGB/语义叠加图核对。通过核验后标为 `semantic_region_verified`。语义标注本身仍不是物理边界真值。 |
| `semantic_bbox_candidate`（网页蓝框/AABB 候选） | 由网页蓝框对应的世界坐标 AABB 构成。当前生成实现见 [emit_hm3d_room_manifest.py](../../tools/rooms/emit_hm3d_room_manifest.py)：按同一 HM3D `region_id` 成员三角面的坐标极值计算轴对齐包围盒。 | 它只说明矩形包住了被标为该 `region_id` 的网格面，不证明该 `region_id` 与目标物理房间一一准确对应，也不表示框内所有位置都属于该房间。因此只作定位、核对和候选边界提示，不能单独作为主指标范围。只有世界坐标和楼层映射可核验时，才可另算 `bbox_proxy_only` 诊断结果，且不与主指标阈值混合；截图像素框不能直接计算世界面积。 |
| `manual_scope`（结构修订范围） | 根据 Habitat 原始 RGB、语义网格和场景结构边界生成或修订的世界坐标 X/Z 多边形；规则房间也可使用矩形。 | 适用于语义区域缺失、错配、不完整或明显跨越目标房间范围的情况。助手先批量生成候选；保存顶点、楼层、证据、原候选框、生成方式、日期、版本和抽查记录；修订结果不能记成官方语义原始范围。 |
| `unresolved`（范围未能确认） | 房间映射、楼层或范围无法确认，或扫描/语义几何不足以核验。 | 标记为不可评估；不猜坐标、不计算主指标、不自动舍弃。 |

各对象分别记录几何来源、核验状态和派生分析类别：

| 字段 | 定义与取值 | 解释 |
| --- | --- | --- |
| `scope_source` | 实际采用的几何来源：语义地面成员面、人工多边形、网页蓝框 AABB 或无。 | 描述几何从哪里来。 |
| `scope_status` | `candidate`、`verified`、`proxy_only` 或 `unresolved`。 | 描述该几何当前核验到什么状态。 |
| `scope_analysis_class` | `semantic_region_verified`、`manual_scope`、`bbox_proxy_only`、`unresolved`；流程中另设 `pending_verification`。 | 未通过自动规则的对象为 `pending_verification`；规则核验通过后进入相应主范围类别，并记录 `verification_method=assistant_auto` 或 `owner_spotcheck`。只有世界坐标和楼层映射可核验的蓝框才可进入 `bbox_proxy_only`，否则为 `unresolved`。未核验范围不进入主统计，也不自动舍弃。 |

### 2.3 网页线框、显示坐标与世界坐标

| 项目 | 定义 | 解释与限制 |
| --- | --- | --- |
| 网页图像归一化矩形 | 在图像坐标中用于显示的矩形。 | 只用于绘制叠加框，不得直接作为 Habitat 世界坐标裁剪 navmesh。 |
| 世界坐标范围几何 | Habitat 场景中的带单位空间几何，并包含楼层归属。 | 主范围核验、navmesh 裁剪和米制面积计算使用它；保存数据字段路径和坐标变换。 |
| 语义成员面渲染 | Habitat 按 `region_id` 给语义成员面着色后得到的顶视图或 RGB 叠加图。 | 用于检查“哪些网格面被标成这个 region”；必要时可为显示隐藏遮挡结构，但须保留场景 RGB 与语义成员面的对应核验图。它不等于物理房间边界真值，图像像素宽高也不作为米制面积。 |

程序对 181 栋的全部对象批量生成范围、地面、家具、楼层和 navmesh 诊断；抽查页只用于负责人核验少量代表样本和高风险类型，不要求负责人逐房确认全量。批量核验图显示原始 RGB、语义 `region` 成员面、网页蓝框、目标范围实线、候选楼层和 navmesh，并执行以下步骤：

1. 自动核对 `room_id↔region_id`、成员面几何、地面覆盖、楼层及坐标映射。
2. 助手给出范围匹配建议和异常理由。
3. 助手按冻结规则为全部对象给出范围来源、状态、证据和异常码。负责人只抽查少量代表样本/高风险类型；反馈用于修正规则并批量重跑同类对象，不要求逐项确认。未经负责人抽查的自动结果须保留 `assistant_auto` 来源标记，不能写成负责人已确认。蓝框坐标映射正确不等于房间范围正确。
4. 若只有截图框、没有可恢复的语义成员面或可靠人工范围，则标记 `unresolved`。只有蓝框世界坐标和楼层均可核验时，才可另存 bbox-only proxy，且不得混入主指标。

保存坐标变换、核验图和代码版本。面积从带单位的世界坐标几何计算。

楼梯与平台作为连接结构单列；不同楼层分别计算。楼层归属不能确认时标记 floor_level_ambiguous，不套用未经核验的固定高度带。

## 3. 指标定义与计算方法

各类面积不得混名或互相替代：

| 字段 | 定义 | 解释 |
| --- | --- | --- |
| bbox_area_m2 | 世界坐标与楼层映射核验通过的蓝色候选 AABB，其 X/Z 长宽乘积 | 只描述矩形包围框，不代表实际房间地面范围或可导航面积；映射未核实时记缺失 |
| semantic_floor_area_m2 | 原始房间清单/网页提供的语义地面三角面表面积；保留原字段名、算法说明和版本 | 只作来源指标或历史对照，不等于水平投影面积或 navmesh 面积 |
| bbox_proxy_nav_projected_area_m2 | 仅在 AABB 世界坐标和目标楼层映射核验通过时，裁切 navmesh 并求水平投影并集 | 仅作框代理诊断；不进入主指标、面积阈值和可用房间结论；映射未核实时记缺失 |
| semantic_floor_after_known_blockers_candidate_m2 | 经核验范围和目标楼层内的语义地面投影并集，减去已识别阻挡物投影并集后的面积 | 本方案主筛选面积。未知/未映射几何不静默扣除或当作确定地面，而是另存不确定叠加与上下界；该几何候选不证明 navmesh 可达或真实任务可用 |
| semantic_floor_conservative_candidate_m2 | 主筛选地面候选再减去与之相交的未知对象及未映射网格投影并集 | 不确定性的保守面积下界，不替代主候选面积；须同时报告不确定面积及原因 |
| specified_scope_nav_projected_area_m2 | 目标楼层 navmesh 面与已核验房间范围几何相交、裁切后投影至水平面并求二维并集的面积 | navmesh 范围支持诊断指标；不是本轮主筛选面积，也不包含 navmesh 外的地面候选 |
| furniture_corrected_nav_area_m2 | navmesh 与语义地面相交并扣除已识别阻挡物投影并集后的面积 | navmesh 支持的地面候选面积；与主筛选面积分开报告 |
| semantic_ground_outside_navmesh_candidate_m2 | 已核验范围内语义地面候选与楼层 navmesh 不相交部分的水平投影并集 | 记录 navmesh 未覆盖的地面候选；已识别阻挡物仍按实例扣除。不得重复加进主面积，也不得因 navmesh 未覆盖而自动判为不可行 |

计算表中即使记录了 `semantic_floor_after_known_blockers_candidate_m2`，也不代表该条已完成范围核验。`scope_status=pending_verification/unresolved`、楼层不明或关键几何异常时，该数值只能作为暂定候选诊断；保留异常原因，禁止纳入主阈值统计或据此自动淘汰。不能计算时记空值和原因，不以 0 代替未知。

页面当前展示的 floor_area_m2 是语义类别地面三角形表面积之和，未做水平投影并集去重，不是本方案主面积；使用前仍须核对当前页面版本及数据来源。

固定计算顺序：

1. 先批量核对 room_id↔region_id 及范围几何。语义成员面可用时，提取该 region 的普通地板、地毯/地垫、浴室/淋浴地面候选并转为水平多边形并集；类别只用于定位地面候选，不直接证明其可行。否则仅使用有结构证据的人工 X/Z 多边形。不得仅用网页像素框或 AABB 代替主范围。
2. 提取同一目标楼层、指定范围内的语义地面多边形和物体实例几何。语义地面投影后求并集；确认阻挡物的三维网格按记录的 agent 身体高度范围投影、裁切到指定范围并按实例求并集，再从地面候选中扣除。未知/未映射投影另存为不确定区域，构造保守下界，不静默归为地面或障碍。
3. 独立提取目标楼层 navmesh，计算 `specified_scope_nav_projected_area_m2`、扣除已识别阻挡物后的 `furniture_corrected_nav_area_m2`，并与主地面候选做几何相交/差集；投影多边形均按同层二维并集计量，避免重复计数。
4. 将语义地面候选与 navmesh 的差集作为 `semantic_ground_outside_navmesh_candidate_m2` 记录。确认是同层地面但 navmesh 未覆盖的区域仍进入主地面候选面积，并标记 navmesh 覆盖缺口；不重复相加，也不把覆盖缺口自动称为不可行。
5. 不同楼层分别报告，不把上下层水平投影重叠区域合并；楼梯单列。坡面按水平投影计量并标记。无法确定楼层/坡面时标异常并排除出主面积，不自动转成负责人逐项待办。
6. 保存范围多边形/成员面来源、坐标、核验方法与抽查状态、floor_id、navmesh 来源、裁切/投影/并集算法、几何库版本、精度参数和结果状态。

若蓝色 AABB 覆盖到邻室/走廊，先将其视为包围盒可能过宽的检查提示；AABB 与邻区相交本身不构成语义区域错误或房间越界证据。应检查实际语义地面成员面和场景结构。若成员面本身明显进入邻室/走廊，再判断是 region 标注错配、开放空间还是正常门口连接。边界清楚时按结构边界修订为 manual_scope；边界无法确认时标记 unresolved 或 scope_spillover，不将其混称为精确房间范围。若确有研究定义需要保留相邻连接面，应另行明确该复合范围并与单房间范围分开报告。

连通分量优先使用 Habitat 拓扑；需要从导出多边形重建时，固定并记录算法和容差。输出 component_count、largest_component_area_m2、largest_component_ratio、候选框长短边、填充率和长宽比；这些仅作描述与复核线索，无独立硬性淘汰阈值。

## 4. 人物代理与 navmesh 核查

### 4.1 人物导入碰撞体

“导入时碰撞半径可能取源半径一半”仍是待核验说法。正式 navmesh 使用前，记录项目实际运行配置中的碰撞类型、有效尺寸、模型缩放和高度。不同模型/导入设置分别记录，不用统一“一半”假设。无法读取时可用已冻结的 agent 配置做试运行，但标记 temporary_agent_proxy。

navmesh 指标只能称为“记录的 Habitat navmesh agent 配置下、经核验指定房间范围内的几何支持面积”，不声称真实人物无碰撞通行。主筛选地面候选面积独立报告，不把 navmesh 支持缺失等同于地面不存在；本阶段不做人物路线实验。

### 4.2 navmesh 配置与静态障碍

记录 Habitat/场景版本、agent 半径与高度、cell size、cell height、最大坡度、最大跨越高度、静态物体设置、navmesh 生成或加载状态及配置文件。旧 navmesh 参数不可核验时标记来源/参数未知，不与统一配置结果混称。

不得仅凭 include_static_objects 的取值断言家具已被作为障碍。核实家具属于场景网格还是独立静态对象，并用顶视 RGB/navmesh 叠加图抽查家具和墙体附近关系；可见家具与可导航区域明显冲突时转人工复核并记录。

## 5. 几何标签与“助手全量处理—负责人抽查”

### 5.1 标签定义

标准化判断问题为：**在经核验的指定房间范围和对应楼层内，是否能看到明确的房间主体可行域？**

| 标签 | 操作定义 |
| --- | --- |
| present（存在） | 范围内有清楚、连续的主体地面候选区域，不只是门口连接带、贴墙窄条或零散网格片；navmesh 支持情况另记 |
| absent（不存在） | 数据和范围可判读，但主要是通道、楼梯、狭长边缘或伪片，没有明确主体区域 |
| uncertain（不确定） | 有有效资料，但扫描、范围几何覆盖、未知物体交叠或主体判读仍不清楚 |
| unassessable（不可评估） | 房间映射、坐标、楼层、场景或语义地面几何失败/损坏，无法计算地面候选；单独的 navmesh 失败只令 navmesh 指标不可评估 |

present、absent、uncertain 是几何判断标签；unassessable 是数据状态。最终 uncertain 的可评估对象在保留率计算中按正例处理；unassessable 不进入阈值统计且绝不自动舍弃。

### 5.2 初判、复核和记录

助手按统一图例对全量房间批量给出建议标签、证据和疑点；项目负责人只查看预先选出的少量代表样本与高风险样本，不逐项审阅全量。负责人反馈用于修正规则，再由助手批量处理所有同类对象。必须分别保留 `assistant_suggestion`、`assistant_reason`、负责人实际抽查时才填写的 `owner_final_label`、`owner_correction_reason`、审核时间和图例版本；未抽查对象不得伪记为负责人确认。该流程不是两名独立人类审核者，也不是双盲审核。不得报告 Cohen’s kappa 或“双人一致率”。

抽查材料统一显示原始 RGB、HM3D region 成员面/候选蓝框、目标范围实线、navmesh 叠加、楼层和物理比例尺；必要时显示 manual_scope 边界。隐藏数值面积、候选阈值、自动舍弃建议和旧 verdict。负责人会看到助手初判，因此不得称“对助手输出盲审”。负责人只抽查冻结名单中的少量样本，不承担全量逐房标注。抽样标签不足以支持阈值验证时，面积自动筛除保持关闭；不能通过要求负责人检查所有房间来补足证据。任何自动舍弃仍须遵守已冻结的验证门槛，未达到门槛时只能输出候选，不能执行。

先用覆盖连接区域、楼梯/多层、不规则边界、多材质地面、扫描缺失和碎片网格的案例冻结图例。规则变更时记录版本并重新复核受影响样本。此处“负责人复核”不是第二位独立标注者，质量结论只针对负责人最终确认的操作性标签。

## 6. 抽样、阈值选择与全范围统计

### 6.1 抽样框与分层

正式统计抽样框为非试运行、至少有一个已核验主范围和可评估地面候选面积的场景；navmesh 是否可评估另列，不单独决定地面候选能否入框。逐房 bbox_proxy_only/unresolved 对象仍记入 181 栋清单，不进入主面积保留率分母，也不自动舍弃。PSU（一级抽样单位）是场景；SRSWOR 表示层内无放回简单随机抽样。助手对全量房间初判；负责人只按冻结的抽样计划抽查样本，不确认抽中场景内的每一个房间。有效人工标签不足以支持目标精度或保留率下界时，相关来源层的自动面积筛除关闭，并报告证据不足。

在标签揭示前冻结场景级抽样层：

1. scope_source_class：主抽样框仅含 `semantic_region_verified` 与 `manual_scope`。一个场景全部主范围均来自核验语义区域时记 semantic_region_only；含任一 manual_scope 时记 contains_manual_scope。`bbox_proxy_only` 与 unresolved 不进入主面积阈值总体，另行计数报告。
2. scene_area_bin：按该场景可评估对象 semantic_floor_after_known_blockers_candidate_m2 中位数分四分位。冻结 NumPy 版本、分位数算法和实际切点。
3. 两字段交叉为层 h。少于 4 个场景的面积层，优先在同一来源类内与中位数最近的相邻面积层合并；并列时并入较小面积层。合并后某来源类总计仍少于 4 个场景时，该来源类场景全部普查并作为已知固定贡献；其面积策略设为 area_filter_off，不参与自动阈值筛除，也不冒充有独立验证的来源域。

每个可推断来源类按第 6.2 节冻结的抽样配置，层内先无放回抽 development，再从未抽中的场景无放回抽锁定 validation；名单、代码、随机种子及各层 N_h、nD_h、nV_h 必须在标签揭示前冻结。Development 权重为 N_h/nD_h；validation 对 development 以外总体的条件权重为 (N_h−nD_h)/nV_h。若剩余总体全查，该权重为 1；小于 4 场景而普查的来源类也作为权重为 1 的已知固定贡献，不参与自动过滤。同场景房间共享场景权重；semantic_region_verified 与 manual_scope 子组按房间来源标记并沿用该权重。验证集只能在阈值冻结后揭示。

试运行场景不进入正式 development/validation，也不套自动阈值；保留人工处理状态并报告 ID。设计试运行和图例校准所用标签均为助手初判后负责人确认的最终标签，不声称双人审核。

### 6.2 样本量规划与场景分配

抽样单位始终是场景；抽中一个场景后，审核其中全部可评估房间。因此样本量不能把房间数当作独立样本后再简单乘一个设计效应换算成场景数。场景内房间数不均、来源构成和场景聚类会共同影响精度与人工工作量，最终分配由基于真实 181 栋清单的完整流程模拟确定。

为使分配可复算，在标签揭示前枚举下列 16 个预先固定的场景抽样比例组合：development 比例 f_D 与 validation 剩余总体比例 f_V 均取 {0.25, 0.50, 0.75, 1.00} 的笛卡尔积。对层 h 中 N_h≥4 的场景，按候选组合计算：
- nD_h = min(N_h−2, max(2, ceil(f_D × N_h)))；
- nV_h = min(N_h−nD_h, max(2, ceil(f_V × (N_h−nD_h))))。
若某层全查，实际样本数按 N_h 记；development 与 validation 名单仍保持不重叠。该设计确保两阶段在可推断层均有至少两个场景；不要求 nV_h≤nD_h。少于 4 场景的来源类按 6.1 全查并关闭该类面积过滤。对剩余场景全查的层，validation 条件权重为 1，有限总体该层结果为已知值。

对每个候选分配，按抽样框清单中每层的可评估房间总数 R_h 计算预期人工复核量：
W = Σ_h ((nD_h+nV_h)/N_h) × R_h。
这是场景等概率抽样下的期望复核房间数，不是独立房间样本量。候选配置按 W 从小到大排序；同值时依次按总抽取场景数、f_D、f_V 从小到大排序。使用独立试运行标签和第 6.5 节冻结的模拟器，依次对配置进行确认模拟，采用第 6.5 节的完整重复数和验收判据；首次通过的配置作为正式分配。确认模拟未通过时按既定顺序测试下一配置，不因结果临时修改网格、目标或判据。若没有配置通过，可对可推断层全查后重新计算；仍不能满足验收，或无法完成规定模拟时，所有未通过来源域设为 area_filter_off，不自动按面积舍弃。

该比例网格是本项目兼顾工作量和可估计性的工程设计，不是统计领域通用标准。5 个百分点的区间半宽目标同样是项目精度取舍，不是普适标准。未达到该精度或覆盖验收时，不以公式估算、点估计或旧阈值替代通过结论。

### 6.3 development 中选阈值

正例定义为负责人最终确认的 present 和 uncertain；absent 不进入正例分母；unassessable 不进入统计且永不自动舍弃。候选阈值按房间范围几何来源分别产生，覆盖 development 面积数据产生的所有严格小于切分，并包括“不筛除”选项。面积严格小于对应 T_g 才成为舍弃候选。

本节及第 6.4–6.5 节中的 `area_i` 均指主筛选面积 `semantic_floor_after_known_blockers_candidate_m2`；范围/楼层未核或关键未知交叠使该值不可可靠比较时，该记录不进入面积阈值拟合与统计，仍保留在 181 栋覆盖清单中。

阈值按房间范围几何来源分别选取，不共用一个未说明来源差异的阈值。对每个拟启用来源域 g∈{semantic_region_verified, manual_scope}，定义 keep_i(T_g)=I(area_i≥T_g)；关闭过滤的域定义 keep_i=1。候选 T_g 为该域 development 面积的全部不同取值（因规则为 area<T_g 才进入候选，T_g 取最小观测值表示不筛除），并包括显式“不筛除”选项。用 development 权重在域 g 内计算正例保留率，选择满足加权保留率至少 95% 的最大 T_g。某域若 development 正例不足两个场景、缺少 validation 支持或数据不可评估，预先将该域设为 area_filter_off。整体保留率按两个来源域各自冻结的 T_g/关闭策略组合后计算，不再另选一个整体阈值；两域均达标时整体加权保留率应不低于 95%，仍须在 validation 检验。development 指标用于选择阈值，**不作为独立验证证据**。

### 6.4 锁定验证与正式抽样框的合并估计

各来源域阈值 T_g 和关闭策略冻结后才揭示 validation 标签。validation 单独计算的结果只表示“development 之外场景”的留出表现；要报告整个正式抽样框，必须合并已普查对象、development 已确认对象和 validation 对剩余场景的加权估计，不能把分开的通过标记直接等同于全范围通过。

对统计域 g（整体、semantic_region_verified 或 manual_scope），令 y_i=1 表示负责人最终标签为 present 或 uncertain，keep_i 为该房间按其来源域冻结 T_g/area_filter_off 策略后是否保留。C 表示 6.1 中少于 4 个场景而全查、预先设为 area_filter_off 的已知固定场景；D 是其余抽样框中 development 的已确认场景；R 是 D 以外的可推断场景总体。C 与 D 均按实际计数计入，且不参与 validation replicate 重抽。分别记：
- P_C = Σ(C,g) y_i，K_C = Σ(C,g) y_i keep_i；area_filter_off 下 keep_i=1，因此 K_C=P_C；
- P_D = Σ(D,g) y_i，K_D = Σ(D,g) y_i keep_i。

Validation 对 R 的加权估计为：
- P_hat_R = Σ(V,g) w_h^V y_i；
- K_hat_R = Σ(V,g) w_h^V y_i keep_i，其中 w_h^V=(N_h−nD_h)/nV_h。若该层剩余场景全查，w_h^V=1，贡献作为已知固定值。

全范围保留率估计为 R_hat_U=(K_C+K_D+K_hat_R)/(P_C+P_D+P_hat_R)。overall、semantic_region_verified 和 manual_scope 分别计算。小于 4 场景而全查的来源类虽无自动面积筛除，其已知正例仍计入对应来源域和 overall；area_filter_off 对应的正例保留率按定义为 100%。Development 在估计中是已观察成员，按实际计数加入，不乘 N_h/nD_h；扩展权重只用于development阈值选择。Validation 权重只代表 D 以外的剩余场景。

对概率抽取的 validation 场景作为 PSU，以层内剩余总体 M_h=N_h−nD_h 为有限总体数，使用 R survey 包的 mrbbootstrap 类型生成 10,000 组 replicate weights。C、D 以及全查的 validation 层都是已知固定贡献，replicate 权重不得改变这些计数；只对存在抽样误差的 validation 层生成 replicate weights。构建设计时记录 R 与 survey 版本、FPC 类型、scale、rscales、MSE 设置及随机种子。先按每组 replicate weights 重新计算 validation 对 R 的正例总数和保留正例总数，再把 C、D 的固定计数加回，形成全范围比率 R_b=(K_C+K_D+K_R,b)/(P_C+P_D+P_R,b)。对 logit(R_hat_U) 使用该 replicate design 的方差缩放设置计算标准误和 t 区间，再反变换为保留率区间；自由度取 validation 随机抽取 PSU 数减去非全查层数。不得只对 validation 子样本计算比率后忽略 C、D，也不得把 replicate 比率原始分位数直接称为 survey 置信区间或逐房 bootstrap。若正例分母为 0、自由度不为正、比例为 0/1 且非全查精确结果、分母不稳定或 replicate 无法计算，区间无效，相关拟过滤域关闭自动过滤。另行报告 validation-only 留出表现，但自动筛除判据使用上述全范围合并估计。

整体、semantic_region_verified、manual_scope 三项使用 Bonferroni 校正，K=3。单侧家族 95% 下界由双侧 level=1−2×0.05/K 的 logit 区间下端给出；同时区间半宽用双侧 level=1−0.05/K 的 logit 区间计算。整体及每个拟启用面积过滤的来源域必须同时满足：全范围合并估计的 Bonferroni 单侧下界不低于 95%；同时区间半宽不超过 5 个百分点；validation 正例至少来自两个不同场景；所有所需区间有效。若整个正式抽样框对相应声明已全查，使用精确结果，不计算抽样区间。Development 的 95% 是选阈值约束，不是独立验证门槛。

整体未通过则任何来源域都不启用自动舍弃；某来源域未通过则只对该域关闭过滤并由助手汇总候选。阈值、关闭域规则及报告口径须在揭示 validation 标签前冻结；验证失败后不得改阈值再用同一 validation 宣称通过。未通过验证时只输出建议，不逐对象要求负责人确认；通过并获得流程授权后才可按冻结规则批量执行。

### 6.5 模拟验收：检验统计流程，不生成房间

正式使用前必须用标签已知的合成有限总体测试完整流程，包括 development/validation 场景抽样、阈值选择、已审 development 与加权剩余总体的合并估计、区间计算和是否启用自动过滤的最终判定。模拟不生成 Habitat 场景、不代替房间审核，也不证明负责人标签是真值。

**模拟总体与生成机制。** 使用冻结的 181 栋场景/房间清单、可评估房间数、实际面积分布、来源构成和楼层结构生成有限总体；仅使用已核验主范围的 semantic_floor_after_known_blockers_candidate_m2。主面积存在未知/未映射交叠、范围未核或楼层未核的记录不进入相应阈值抽样框，并保留异常状态。按场景生成共享随机截距，保留实际每场景房间数和来源构成，不把房间行打散为独立样本。令 M_i=1 表示 manual_scope、否则为 0；x_i=(log(area_i)−mean(log(area)))/sd(log(area))；q_i=(x_i²−mean(x²))/sd(x²)，均在冻结的正式抽样框上计算。若相应标准差为 0，该特征置为 0，依赖该特征的效应情景记为不可识别，不得声称已通过该类压力测试。固定标签模型为：
logit(P(y_i=1)) = α + γM_i + β₁x_i + β₂q_i + δ(M_i×x_i) + u_scene，
其中 u_scene 独立服从均值为 0、标准差为 σ 的正态分布；y_i=1 表示负责人终审标签为 present 或 uncertain。
预先冻结以下参数情景族：
1. 面积无关联：β₁=β₂=δ=0；
2. 单调关系：β₁取 log(1.25)、log(1.5)、log(2) 及其相反数；
3. 非单调关系：β₂取 log(1.5)、log(2) 及其相反数，覆盖 U 形和倒 U 形；并加入 β₁与β₂同时非零的情景；
4. 来源差异：γ取 0、试运行点估计和其场景 bootstrap 区间端点，以及 log(1.5) 和其相反数；来源×面积交互 δ取 0、log(1.5) 和其相反数。
这些优势比和正例比例是本项目预先选定的压力测试网格，不是 HM3D 的实测规律或领域通用标准。对每个机制族，正例总体比例至少覆盖 20%、50%、80% 三种情形；截距 α 通过数值求解校准至对应比例。场景随机截距标准差 σ 取 0、试运行估计值及其场景 bootstrap 95% 上界。试运行估计或区间不可稳定获得时，记录不可估计并关闭相关自动过滤，不能只挑选对面积筛除有利的参数。所有特征变换、参数组合、软件版本、求解容差、收敛状态均写入冻结的模拟清单。

**边界情形和模拟分阶段。** 使用独立的模拟调试阶段检查生成机制及代码，不把调试重复计入验收。调试阶段选定并冻结能覆盖真实正例保留率低于 95%、接近 95%（94.5%–95.5%）和高于 95% 的配置；至少包括无面积关联和来源×面积差异情形。这里的真实保留率由合成有限总体完整标签对每次模拟所选策略事后计算，仅供模拟评分；阈值选择算法不得读取 validation 或未抽中场景的标签。若预设参数网格无法产生三类边界情形，扩大参数网格的规则必须在验收运行前写入模拟清单；仍无法构造关键边界或参数依据不可靠时，不启用自动过滤。完成调试后冻结代码提交/哈希、配置、参数、随机种子及边界情形；以新的、预先记录的种子运行验收，调试结果不得并入验收统计。

**验收重复与判据。** 对每个冻结的主要情景至少运行 1,000 次完整流程；每次概率 validation 区间使用 1,000 组按场景抽样设计生成的 replicate weights。每次运行都保存抽样名单、分层/权重、development 选出的阈值、总体真实保留率、估计值、同时区间、启用判定和失败原因。对 overall 及两个来源域报告家族同时区间覆盖率、真实保留率低于 95% 时错误启用自动过滤的比例、区间半宽、无效区间/零分母比例及相应 Monte Carlo 区间。各主要情景家族覆盖率须为 93%–97%；真实保留率低于 95% 的关键情景中，错误启用率的单侧 95% 精确二项区间上界须不超过 7%。报告每项比例的分子、分母和 Monte Carlo 区间；未达到最少有效重复数、区间无效或关键情景未通过，都按失败处理。

模拟参数网格、边界筛选办法、随机种子、代码版本和验收门槛均须在正式 validation 标签揭示前冻结。任一主要情景未通过、无法复现或无法完成规定计算时，不启用受影响来源域的面积自动舍弃。该模拟只说明统计流程在这些明确假设下的行为，不是领域普适保证，也不证明筛选标签的客观正确性或下游任务适用性。

## 7. 旧规则、处理建议与裁剪

旧流程 6 m²、50 m²、短边 2.2 m 仅作历史基线。先核实旧代码各值使用的字段和单位；无法核实的标记未知，不得直接套到 semantic_floor_after_known_blockers_candidate_m2。50 m²只触发大范围复核/裁剪候选检查，不自动裁剪。

房间类别单独记录，不代替几何标签或边界。项目处理建议分为保留、舍弃候选、裁剪、存疑：

| 建议 | 原则 |
| --- | --- |
| 保留 | 指定范围几何和楼层可评估，负责人最终标签为 present；类别目标性另记 |
| 舍弃候选 | 明确非目标类型、最终标签为 absent，或通过全范围验证的面积策略列为候选；实际执行前负责人确认 |
| 裁剪 | 有可复核的墙、门洞或功能边界，生成子框并重新计算 |
| 存疑 | 范围几何、楼层、扫描/navmesh/家具关系不清或标签为 uncertain |

主指标按已核验的指定范围几何计算。只有任务明确要求形成新的房间子区域时，才沿可复核的真实墙体、门口或功能边界裁剪；不得按面积、颜色、bbox 中点或方便程度切割。开放空间无真实分界时保留为复合范围或存疑。裁剪记录原 ID、前后范围几何、floor_id、依据、操作者、抽查状态和时间；子区域作为新对象重新计算范围内 navmesh 面积、连通性和形状。孤立小区域不能仅因面积小删除。

### 7.1 可行域面积完成后的后续场景筛选（当前执行初筛）

本节定义当前初筛与正式审核 verdict 的区别。负责人于 2026-10-06 明确采用 `10 m²` 作为本项目的房间候选面积下限：这是项目任务门槛，不是领域通用标准，也不等同于第 6 节的统计阈值。助手需对全队列一次性给出保留候选、舍弃候选、裁剪候选或存疑状态；这些派生建议不删除原始对象，也不改正式审核 verdict。

主面积为同层语义地面扣除已识别阻挡物后的几何面积。探针只作碰撞/漏区对照：探针可达不直接并入，探针面积不替代、不设为主面积下限、也不按栅格值加减。对探针发现的候选逐块核实地面类别、楼层、物体阻挡、墙体/门洞和空间归属；证实为目标地面漏提取后才将其几何并入。青色 AABB 只作参考；明确人工排除的相邻空间优先。当前运行数据和未决范围见 [运行摘要](EXECUTION_SUMMARY_20261007.md)。

形状初筛使用全量几何指标。项目执行提示为：至少两个面积不小于 `0.5 m²` 的连通块且最大块占比低于 `0.5`，标记为“缺少主导连续主体”舍弃候选；长短轴比不小于 `5` 且最大连通块局部宽度中位数低于 `0.8 m`，标记为“狭长条带”舍弃候选。上述数值是本轮项目操作条件，须与面积、场景类型分开记录；任何几何/覆盖异常先标待核，不以分位数本身自动淘汰。纯楼梯/纯走廊只有在范围内结构证据或负责人明确意见支持时才作场景不适合候选，语义标签出现本身不够。

`≥50 m²` 的已核主面积列裁剪候选，须沿真实墙体、门口或明确功能边界切分；框外候选可能使面积超过 `50 m²` 时加范围敏感标记，但不据此虚构切线。面积、范围和形状结果都按逐对象报告，不能把可能重叠的房间面积相加为房屋总面积。

| 后续筛选观察项 | 可形成的候选处理 | 判定边界 |
|---|---|---|
| 筛选理由编码 | 面积、`scene_type_unsuitable`、形状/连通、范围和数据质量理由分开记录；允许多标签并存 | `10 m²` 是项目适用性面积下限；未核实的框外范围按范围补全候选/存疑处理，不能将探针栅格值冒充主面积。场景类型按空间证据单独判断。 |
| 主要是楼梯、走廊或狭长连接带，缺少明确房间主体 | `absent` / 舍弃候选 | 依据已核验范围内的空间结构，不依据 AABB 长宽比单独判定。 |
| 家具（例如床、沙发）占据大部分范围，剩余位置可能不足 | 小可行域复核 / 面积门筛除候选 | 报告 `semantic_floor_after_known_blockers_candidate_m2`；按项目 `10 m²` 下限筛选。范围/楼层未核时标范围补全候选或存疑；不可评估值不按 0 处理。语义地面、navmesh 和探针面积分别报告。 |
| 缺少家具或特定场景内容 | 任务内容复核 | 只有后续任务明确要求某些家具、交互对象或视觉背景时，才可据此提出舍弃候选。先列出必需类别；在需求未冻结前，“没有家具”只记观察，不作为通用硬门槛。 |
| 候选范围可能包含多个房间或明显过宽 | 范围复核 / 裁剪候选 | 依据墙体、门洞或明确功能边界建立新的 `manual_scope`，裁剪后重新计算。AABB 大、虚线框大或框内包含不同地面颜色都不能单独触发裁剪。 |
| 面积、地面覆盖、物体占地或楼层仍有技术异常 | 存疑 / 返修 | 先修正计算和范围证据，不把技术失败当作房间不适用。 |

家具状态统一记为 `present`、`none_observed` 或 `unknown`。自动几何流程识别出阻挡物实例时可记 `present`；仅仅没有识别到阻挡物，不能记 `none_observed`，必须保留为 `unknown`，除非完整 RGB/语义覆盖经过人工观察确认无家具。空间类型同样只有在实际范围证据或负责人文字明确支持时才记录；未分类不得从 AABB 形状推断为走廊或房间。

后续筛选区分统计阈值与项目操作面积下限。当前 `A_task_min=10.0 m²` 为负责人指定的项目任务下限；探针仅用于发现可能漏算的同层地面补片并核实碰撞/连接，不将探针采样面积直接加进主面积。`00487/R10` 的“缺少家具”、`00064/R13` 的“床占比大、剩余区域小”和 `00757/R17` 的“楼梯/走廊为主”仍按独立原因记录，不推断未提供的家具任务需求。

所有对象先完成面积核算，再分别应用空间类型、面积和形状规则；不能把三类理由合并成一个面积门槛。面积门筛选对象只进入派生候选清单，不跳过面积记录，也不直接改正式人工 verdict。

后续记录 `post_area_screening_status`（not_started、keep_candidate、discard_candidate、crop_candidate、review）、`post_area_reason_codes`、证据/范围版本和负责人最终决定。若任务要求家具/场景内容筛选，另记录 `task_context_inventory`（任务要求类别、观察到的实例、presence/absence/unknown 和证据路径）；任务清单未冻结前只作描述。助手建议只产生候选，不自动删除对象或改正式审核 verdict。

## 8. 异常处理、输出与可复现性

以上异常由助手全量检查并按原因归类。负责人只抽查少量代表/高风险样本；未解决对象继续标记 `review/unresolved`，不得汇总成要求负责人逐房处理的待办清单。自动面积舍弃若未通过冻结验证则不执行；若通过，则依冻结流程批量应用并抽查结果。

## 9. 试运行与验收

先用少量代表性案例验证 room_id↔region_id、成员面几何提取、蓝框到世界坐标的映射、语义/人工范围核验图、范围裁切、楼层分离、投影并集和异常标记。抽样覆盖 semantic_region_verified/manual_scope、蓝框不匹配、不同面积分位、框跨走廊、门口连接、楼梯/多层、不规则房型、多材质地面、扫描缺损、家具冲突和 navmesh 重叠。试运行数据与正式验证样本隔离。

正式处理验收条件：

1. 181 栋所有原始房间都有明确状态，无静默漏项。
2. semantic_region_verified、manual_scope、bbox_proxy_only、unresolved 分开计数；蓝框只作为候选显示，其 room_id/region_id 映射和成员面几何经核验。
3. 主筛选面积 `semantic_floor_after_known_blockers_candidate_m2` 按已核验范围、floor_id、同层语义地面水平投影并集减去已识别阻挡物投影并集计算；未知对象/未映射几何单列不确定面积与保守下界。navmesh 面积及其地面覆盖差异另列；bbox_proxy_only 不混入主面积和主阈值。
4. 网格参数和静态障碍状态已核查或明确标未知；临时代理未混入标准结果。
5. 助手初判、负责人实际抽查样本的最终标签、改判理由和图例版本可追溯；未抽查对象不得伪记成人工确认，也不报告双人一致性。
6. Development/validation 场景名单、分层、条件权重和全范围合并估计可复算。
7. 完整阈值流程模拟达到预设覆盖率与误通过验收；未通过不得自动舍弃。
8. 全范围合并估计的下界、区间宽度和有效场景条件通过后，才启用相应来源域的自动面积候选。
9. 只有通过冻结统计验证且已授权的面积规则才可批量筛除；未通过时只给候选建议。不可评估对象永不自动舍弃，负责人只抽查代表结果。
10. 裁剪有真实边界依据且裁后重算；原始数据和正式审核标注未修改。

## 10. 允许的结论表述

> 在团队已下载的 181 栋场景中，助手批量核验 HM3D 语义 `region_id` 与审核对象的对应关系及成员面几何；网页蓝框仅作语义区域 AABB 候选。通过规则核验的语义区域或有证据的人工范围作为指定范围，在楼层隔离条件下计算语义地面投影并集，扣除已识别阻挡物占地，作为主筛选面积；未知/未映射交叠另列不确定区域及保守下界。Habitat navmesh 支持面积和 navmesh 外地面候选分别报告，不相互替代。项目负责人抽查少量代表/高风险结果，反馈用于修正规则并批量重算；未抽查项保留自动来源与异常状态。只有蓝框而范围无法核验的对象单独报告，不混入主阈值分析。面积阈值验证是后续独立步骤；人工样本不足时关闭自动面积筛除。

主面积是经项目核验范围内的 Habitat 语义地面几何候选，不是精确墙内净面积或真实人物可达性的证明；navmesh 支持面积也只是记录配置下的几何代理。二者均不证明实际声学/摄像机/物品布置适用性。结论不外推到 181 栋以外场景。
