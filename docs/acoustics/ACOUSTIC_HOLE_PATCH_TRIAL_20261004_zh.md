# 声学网格补洞试点（2026-10-04）

本工具只为声学派生网格产生候选四边形与独立新版本。原视觉 GLB、语义、导航、已有声学包、验收代码和门槛保持只读。无法确定为扫描缺失的开口不补，保留逐候选待审原因。

## 规则与安全检查

先按原漏出射线在同一扫描 AABB 面上的穿出点聚类，再结合真实语义网格边界闭环。闭环必须平面化、邻接结构语义、对应实际漏出射线；门窗、未知表面以及可能是真实开口的较大墙孔保持待审。边界碎裂的水平孔另以已有地板/天花板平面与外围八处结构支撑判断。具体常数在 `src/avengine/acoustics/hole_patch.py` 的 `RULES` 和函数中。

候选四边形留 5 cm 余量，向房间外偏移 3 cm。检查全部原摆位算法有界候选点之间的直达线超集；整块四边形与原导航三角形的可走体连续裁剪；从所有相机候选位置做门窗保守包围盒的连续视锥检查。任何视锥交叠都待审，避免射线采样漏掉细窄开口。原始 GLB 的 CPU 首命中射线只用于额外证据，保留所有原始面，不创建视觉 Simulator 或 GPU 渲染器。

继承相邻表面的原语义 material_id、映射及声学系数，不重新随机材质。窗口只能按玻璃假设处理，并须有通透视线证据；本版本不自动放行窗口候选。原系数仍是既有研究假设，不等同实测材料真值。

尝试整屋外包壳时先生成六面候选。未能证明全部漏出是扫描缺失、真实外部门窗被保留、立面与材质可靠时，不上传完整闭壳做传播。这种情况明确记为待审和原生传播未运行，不能给出虚构救回数或 RT60 效果。

## 派生包和验收

实际补片只追加每块 4 顶点、2 三角形。通过显式声学专用 GLB 和原编译器生成新研究包，逐项验证原顶点、原面、原 material_id 不变，并通过原契约及原生 RLR 上传。内部 compiler room manifest 的 GLB 仅为声学编译输入，不用于视觉场景。没有补片时产生完整新目录副本并记录 `operation=no_op`。

原 `tools/acoustics/accept_houses.py` 直接测每屋原先预选房间，旧包和新版本各独立传播一次。实际有补片的屋再用该工具的一房模式复测全部候选房（每间 8 RIR、2 听者、3 FOA 位置）。保留所有原门槛及首到达 +0.5 ms 窗；不把未实测候选房计为声学救回。

## 运行顺序

外部路径由命令行和输入 manifest 提供；所有新产物、缓存、原生临时文件及测试临时目录设在独立试点输出根。使用已安装的 CPU 运行环境，设置空 `CUDA_VISIBLE_DEVICES` 与单线程 BLAS/OMP，不改变共享环境。RLR 保留原 manifest 的 8 线程设置。

1. `hole_patch_trial.py prepare`：快照输入，预先选 3 HM3D + 2 MP3D 试点及 5 + 5 合格对照。
2. `hole_patch_trial.py allocate`：当时 `/proc/stat` 一秒采样，分配少量空闲 CPU。
3. `run_hole_patch.py evaluate --stage pilot`：完成 5 套候选、检查和原生对拍。
4. `run_hole_patch.py freeze`：固定参数、试点名单和决策实现身份；之后不按批次结果调整规则。
5. `run_hole_patch.py batch`：同一冻结规则跑全部被卡房屋与对照。
6. `verify_hole_patch_rooms.py`：实际补片房屋的全部候选房逐间对拍。
7. `report_hole_patch.py`：中文报告、逐套 CSV/JSON、对照差值分布、真实补片 RT60 分布和自包含一页离线 HTML。

原生随机传播不会保证晚反射或 RT60 逐位相同；因此同轮旧包基线和 no-op 对照单列重复性分布。窗口、真实门洞、外立面证据不足以及正式视觉/实测材料真值缺失分别记录，不因漏声下降就放行。

本任务的执行快照、冻结时间、全部原生日志、报告、离线页和提交身份位于 owner 指定的独立试点产物根。此源码提交不包含数据集、网格或媒体，不 push，不发送 owner。
