# 酷家乐房间合法性预检

这套工具输出“房间 × 资产类别”的摆放候选，用于出题器提前筛选房间和附着面。
它不生成父场景、音频、问题或训练表，也不替代最终生产门禁。

## CPU 原生几何

`tools/ue/check_kujiale_room_legality.py` 按明确指定的训练房名单，
读取既有 UE LOD0 和已导入个体的实际顶点。人使用已正式通过的站姿
`GetActorBounds` 保守包围盒；狗、猫、带架鸟和物件使用实导入顶点。
检查真实房间地板身份、贴附、完整 OBB 与家具/墙的相交、接触负例，
并保存相机候选。物件类型与附着面分别列项，动物不替换为其他品种。

正例只适用于记录中的代表个体和尺寸，不能推广到未测试的外观、动作或同场组合。
没有找到候选时保留采样范围与失败原因，不声称物理上绝对放不下。

`avengine.capture.kujiale_room_inputs.prepare_room_inputs` 保留原 UE 已准入
`floor_reference`，把 CPU 新点存入 `cpu_planning_floor_reference`。
CPU 点不会被改写成原生实测通过。规划使用 `floor_reference_for_planning`；
准入检查使用 `admission_floor_reference`。

## UE 房间出图和摆放点可见性

`tools/ue/capture_kujiale_room_legality.py` 使用生产 UE 工程、原生灯光和
曝光配置，显式选择每个 `room_id`，避免只检查一套房的第一间房。
在任务私有 GPU2 设备命名空间运行时指定 `--gpu 2 --graphics-adapter 0`；
启动前查显存，随后核对 UE PID、Vulkan 设备 UUID 和 NVML 原生图形进程。
相机位置误差限 0.5 mm、角度限 1e-4 度，摆放点深度遮挡容差 5 mm。

原生渲染的是房间；可见性结论针对清单中的空摆放点，不冒充个体完整资产遮罩。
每个资产原有三视角验收、高光、发声点、动作和最终同场门禁继续由生产线执行。

## 使用边界

所有参数通过 CLI 提供，结果只写入指定任务输出根目录。作业要求 nice >=10；
进程、PSS、GPU 和新增磁盘预算由任务守卫执行。已完成的逐房 JSON 和图片
拒绝覆盖，恢复时直接读取。相同房间的新修复应使用新的证据目录。

出题器只消费最终清单明确可用的代表资产/摆放点，仍需当场重测颜色、
保留地板身份检查、RIR 方向、真实可见发声体和独立真值重算。
空调是无声摆设。任何预检结果都不能把 `not_run` 转成正式父场景通过。
